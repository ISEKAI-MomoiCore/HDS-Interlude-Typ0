## 1. 已定位与修复的问题

| 类别 | 根因/表现 | 修复 |
| --- | --- | --- |
| SnowLuma 状态卡缺边 | 警告色引用了未定义的 `--kiy-sand`，整条左边框声明失效 | 使用标准警告色 token，并提供后备颜色 |
| 右侧摘要网格线重叠 | 网格容器与各单元格分别画边，内部线条归属不清；旧背景选择器还会覆盖分隔线背景 | 外框加 1px gap 统一绘制共享线，单元格不再重复画边；补足选择器优先级 |
| 切换主题丢外框 | 账号列表、端点设置卡片只有默认主题定义了结构边框 | 为其他主题补通用结构外框，不覆盖默认色板及阅读列表的单分隔线设计 |
| 标签页/菜单细节 | 末个标签重复画右边、分段按钮焦点边界拥挤、测试区与底部操作区重复分隔 | 收敛末项边线和焦点描边，移除重复底线 |
| 账号下拉不可逆 | 选“手动输入”后难以回切，编辑时可能跳回第一个检测账号 | 保留选择器；编辑按 Self ID 精确选中；未检测到的既有账号保留手填状态 |
| 平台按钮只是装饰 | 平台选择只改变颜色，没有传入账号配置流程 | 平台与向导通道联动，并同步 aria-pressed；不同通道不读取隐藏 QQ 下拉值 |
| 端点与账号脱节 | 选择其他账号后端点没有按该账号更新 | 联动该账号配置的端点；不把“发现配置”当作“账号已在线” |
| 多账号误操作 | 某卡片编辑选了第一条账号，解绑调用遗漏 Self ID 导致全解绑 | 编辑和解绑均传精确 Self ID，只作用于目标账号 |
| 账号编辑清空端点的假成功 | 旧注册逻辑会保留未传入的端点，界面却可能让人以为清空成功 | 编辑既有账号清空端点时阻止保存并提示；停止接入应明确解绑目标账号 |
| 连接测试与保存竞争 | 连点可重复请求，修改输入后旧探测结果回写，保存时仍可关闭或修改表单；测试中保存失败还会锁死测试按钮 | 探测版本号丢弃过期结果，提交防重入；保存期间锁定控件与关闭操作，失败后恢复按钮并清除过期测试提示 |
| 通知遮挡操作按钮 | 弹窗里的错误浮条绝对定位在底部，实际盖住取消/保存并拦截点击 | 非交互通知不拦截鼠标；弹窗通知预留正常布局空间，不再叠盖操作区 |
| 空令牌语义不清 | 测试未沿用已保存令牌；账号/端点变更后仍可能误用旧令牌 | 区分手填、沿用保存值、显式读取本机 SnowLuma 三种来源；后两项互斥，手填优先 |
| Mixer 下拉/数字操作别扭 | 每次修改重建整张卡片，节点与键盘焦点被销毁 | 局部刷新草稿标记、撤销状态和继承提示，不重建输入节点 |
| Mixer “继承”没有真正生效 | 前端清空值后，主进程仍保留旧覆盖值 | 清空枚举/数字、切到三态开关“继承”时发送 null；主进程删除对应覆盖字段，不向 YAML 写 null 或 NaN |
| 布局菜单键盘不连贯 | 缺少方向键定位和 Escape 返回触发按钮 | 支持方向键、Home/End、Escape 与焦点回归，保留菜单互斥和外部点击收起 |
| SnowLuma 运行检测错误 | 实际以安装目录中的 `node.exe index.mjs` 运行，旧实现只查 SnowLuma 名称 | 检查进程入口与 `@snowluma/*` 包信息；优先运行目录；进程检查失败显示未知，不冒充未运行 |
| WebUI/登录混为一谈 | 固定端口或 WebUI 可达容易被误当作账号登录成功 | 从 runtime.json 获取管理端口，分离进程、管理页面可达、get_login_info 身份验证三层状态 |
| OneBot 401 提示错误/刷重连 | 鉴权失败被当成普通网络失败，关闭回调覆盖原错误并重复重试 | 单独的 ONEBOT_AUTH_FAILED 分类和中文提示；401/403 停止无效重连，等待用户修正配置 |
| 账号状态显示不准 | 前端读取 externalState，但 accounts:list 未提供；连接恢复可能残留错误 | 主进程提供状态/错误码/安全提示；在线或重新连接时清除旧错误上下文 |

## 2. 凭据安全与本机实测

### 本机只读验证

已检查本机正在运行的 SnowLuma 1.14.0：

- 安装目录：`C:\SnowLuma-v1.14.0-win-x64`。
- 真实运行方式为 bundled Node 加 index.mjs，修复后的检测结果为 running。
- 管理页面端口 5099 可达，返回 HTTP 200。
- 发现 3 份账号配置；**配置存在不等于对应账号在线**。
- 当前在线账号在端口 3001，使用该账号、该端点匹配的本机访问令牌，get_login_info 身份验证通过。
- 另一个配置也使用 3001，但它的令牌不匹配当前监听账号；3002 的配置当前没有可达服务。不能把这些配置全部标为在线。

验证只执行 get_login_info，没有发送真实消息，没有启动/停止 SnowLuma，也没有改写真实账号配置或凭据。

### 安全边界

- WebUI 密码不是 OneBot access token；本次没有关闭或绕过鉴权。
- 本机令牌读取只在用户明确选择后发生，且限 loopback WS、精确 Self ID/端口/路径和唯一匹配配置。
- 令牌不下发 renderer，不放 URL，不写入测试报告和普通错误信息。
- 已保存令牌仅允许同剧本、同账号、同端点复用；新令牌由主进程写密钥库，使用独立 alias，绑定失败清理新 alias。
- 上游探测不跟随重定向，不将凭据发给跳转目标。

### 旧账号如何应用修复

1. 重启桌面软件，加载新构建产物。
2. 若目标剧本 Worker 正在运行，先卸载 Worker，再编辑账号配置；原有运行中配置保护没有取消。
3. 进入“连接与账号”，选择具体账号的“配置端点”。
4. 核对账号与端点，勾选“使用本机 SnowLuma 配置中的令牌”；已有手填错误令牌时先清空输入框，因为手填值优先。
5. 点击“测试连接”，身份验证成功后保存端点。随后按原流程重新加载 Worker。

本次**没有悄悄覆盖现有密钥**。旧配置如果保存了错误令牌，需要按上述步骤重新选择来源并保存；不能仅凭进程识别修复就宣称旧 401 已自动消失。
