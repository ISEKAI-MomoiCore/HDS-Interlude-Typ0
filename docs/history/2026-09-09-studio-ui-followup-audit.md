日期：2026-09-09。对照：`2026-09-09-studio-ui-audit-and-repair-plan.md` 与当前 `desktop/src/renderer/`、宿主 Mixer API。仅新增本报告，不修改业务代码、配置或数据。依据静态调用链、源码/产物指纹和隔离函数验证；未对运行中的真实故事操作或采集帧率。

## 1. 结论

上次方案有实际落地，但没有完成架构闭环。`DESKTOP-DESIGN.md:1438` 的“37 项全部处理”不应继续作为验收结果：其中不少只增加了注释或局部修正，还有后续新功能重新覆盖修正的情况。

当前不流畅主要由三个共同问题造成：

1. 时间视窗、虚拟画布、原生 scrollLeft 与总览拖拉条同时决定位置，没有唯一状态来源；部分刷新只改变坐标参数，不同步已绘制对象。
2. 用 story/revision/view 一个缓存键阻止整页重画，却漏掉轨道显隐、视窗变化和选中状态，导致该更新的不更新；新 revision 到来又整页销毁，打断已有节点。
3. 新旧实现并存。最明确的是两个 `loadMixerStrips` 和两个 `flushMixer`：后定义的旧版覆盖前面的新版，使分组 UI 首次进入失效。

检查时 HDSI 依赖为 beta16，桌面包版本仍为 `0.0.1-m0`。三个 renderer 文件的 src 与 dist 哈希均一致。问题已经存在于当前构建产物，不能归结为忘了 build；本次未确认正在运行窗口是否仍保留更早的内存代码。

## 3. 当前最需要处理的问题

### T01：滑动速度过快，是输入处理公式造成的（最高优先）

位置：`app.js:676,1538`。

横向滚轮只取 delta 的正负，不读取大小或 deltaMode；每个事件移动 `span*0.32`。14 小时视窗一次事件就跳 **268.8 分钟**；十个同向事件跳 **44.8 小时**。触摸板一次轻划可能产生多次事件，这足以解释飞速滑动。

Ctrl 滚轮每事件乘 1.2/.83，十个缩小事件把范围扩大约 6.19 倍。两倍率也不严格互逆。调低 0.32 只能改善某一设备，不能统一触摸板与鼠标。

修复清单：

- [ ] 将 deltaMode 转为 CSS 像素，依据实际 deltaX/deltaY 积分位移，再用 pxPerMs 换算时间。
- [ ] 横滚与纵滚有明确路由；只有 timeline 活跃才接管。Session/Mixer 的滚轮不应修改隐藏的时间轴。
- [ ] 缩放使用连续指数倍率，围绕鼠标时间锚；保留小数跨度，去除整分钟 rounding。
- [ ] pointer/wheel 每帧合并一次绘制，localStorage 在手势结束或空闲后写一次。
- [ ] 验收：同一总 delta 分成 1/10/100 个事件，结果接近；缩放正反相同 delta 回到原跨度；细小触摸板输入不会跨越数小时。

### T02：拖拉条的坐标范围会变，而且显示没有跟上拖动

位置：`app.js:635,1891,1917`。

pointerdown 捕获 b.totalSpan，移动据此改变 viewport；但 updateViewport 不即时更新滑块窗口。滑块通常等防抖快照/其它刷新再变化，刷新时又从新视窗重算 totalStart/End。于是手指在移动，滑块像没动，随后重新定位。NOW 还被 app.js:2055 每 200ms 用另一范围重写。

修复清单：

- [ ] overviewRange 成为独立、稳定的导航范围，不由当前视窗每次重新推算。
- [ ] 手势期间冻结 overviewRange 与起始 rect；拖动每帧同步滑块和轨道画面。
- [ ] 每个 NOW 元素只有一个位置更新来源；总览标记始终用 overviewRange。
- [ ] 空白点击明确“居中到该时间”；删除多余半屏偏移。
- [ ] 手柄先夹活动端，再由固定端算 span/center，达到边界不移动未拖动端。
- [ ] 用 pointerId 管理捕获和取消，拖动期间快照不得重新定义坐标。
- [ ] 验收：拖动时滑块跟手；停止 300ms/15s 后不再次跳动；30 秒长拖含数据更新，固定端仍稳定。

### T03：虚拟画布仍然是每次重建的坐标，不是稳定滚动画布

位置：`app.js:58,635,688,950`。

updateCanvasFromViewport 每次把 origin 设为 viewport.from−span，同时重新计算像素密度。renderArrangementScale 也会调用它，但只重画标尺，不更新所有 clip。这样新参数与旧 clip 像素能同时存在。原生横向滚动没有对应 scroll 监听把位置写回 viewport，随后刷新又用旧 viewport 设置 scrollLeft，回弹是预期代码结果。

当前缓存键只有 storyId/revision/browserView。换视窗可能 revision 不变；此前窗外 clip 创建时被过滤，平移后仅移动已有节点，新可见对象不补画。轨道开关也没包含在 key 中，可能菜单已变化但轨道未变化。

建议采用一个简化的可见区模型：`viewStartMs + scale + laneRect` 是唯一视图状态，画布对象位置由它生成；总览滑块和滚轮都是修改这份状态。若继续采用原生 scrollLeft，必须把 scroll 作为输入并区分程序滚动，重设 origin 时补偿偏移。两种方案择一，不能继续混合。

- [ ] 分离 dataRevision、viewRevision、layoutRevision、selectionRevision，避免一个字符串缓存全部功能。
- [ ] 每帧重算可见对象 ID 集合，只增删必要节点；没有数据变化也应正确切换显隐、预览和选中样式。
- [ ] viewport 未变的只读函数不得修改 canvas；一帧共用一个 now 和 geometry。
- [ ] 布局改变用 ResizeObserver 重测 laneRect，保持中心时间或鼠标锚，而非等待下一次刷新。
- [ ] 验收：拖原生横条、开关轨道、调侧栏、固定视窗等候刷新，均不回弹、不留空轨、不发生旧像素错位。

### T04：背景标尺没有使用同一组刻度

位置：`app.js:688`、`index.html:39,43,51`、`style.css:7`。

刻度文字已经改时间步长，但背景仍是 10% 或 25% 的 CSS 渐变。每个格子没有稳定时间含义。标尺宽度被设置成三屏，靠负 margin 平移，没有专门的可见裁剪 viewport；自身 overflow:hidden 只能裁到三屏边界。轨道头 JS=132，窄屏 CSS=108，标尺右侧又保留60px。

- [ ] 以 laneRect 为唯一原点，轨道头宽度由 CSS 变量统一读取。
- [ ] 时间轴 viewport 单独 overflow:hidden；内部 ticks 层使用 transform，不改变 grid 布局宽度。
- [ ] 同一 tick 数组同时画文字、主格线和次格线，废弃百分比时间网格。
- [ ] 根据像素间距选择刻度密度，跨天显示日期，格式统一故事时区。
- [ ] 验收：0/25/50/75/100% 五个位置的同一时间点跨轨误差≤1 CSS px；拖动、缩放、125%显示缩放后仍成立。

### T05：NOW 播放头可能刷新一次就消失

位置：`app.js:962,2020`。

NOW 节点放入 Arrangement；新 revision 时 replaceChildren 删除节点。ensureNowPlayhead 因旧引用非空立即返回，动画继续修改一个已脱离文档的节点。sticky 也不适合表达自由时间位置：left 是粘滞约束，不是普通内容定位。

- [ ] 持久 overlay 放到可重建内容外，用 absolute/transform 显示，裁剪范围明确。
- [ ] 生命周期判断至少包含 isConnected；更好的方式是内容重绘不销毁 overlay。
- [ ] 历史窗口不强行延伸到 NOW+5min；NOW 在窗口外显示方向提示。
- [ ] follow 模式维持显式固定视窗，到阈值才移动，避免每次读取都重新居中。
- [ ] Session/Mixer/Stats 不显示时间线覆盖层。

### T06：当前避让算法仍会叠字

位置：`app.js:898`。

三行循环分配使第四个并发事件回到第一行；14px 间距小于常见27px块高。算法用假定30秒而非实际时间区间/视觉宽度，缩放后布局不重新计算。

- [ ] 根据实际可见区间及命中宽度做子行分配；行距≥块高+间隔。
- [ ] 密集点事件远景聚合为带数量标记，近景展开；不要无限扩轨，也不要循环覆盖。
- [ ] Script 的确认区间与推断尾部继续区分，重叠 Script 也需显示/选择策略。
- [ ] 预览按像素面积和字体测量选择容量；缩放时更新预览，不只改外框。

## 4. Mixer：这次不仅是排版问题

### M01：旧版函数覆盖新版（最高优先）

`app.js:1681/1797` 两次声明 loadMixerStrips，`1783/1827` 两次声明 flushMixer。隔离执行函数声明后检查有效函数，确认最终读取入口是后面的 `params.forEach` 旧版。

首次进入会把全部参数、不论 section/type，一律画 range input。toggle/select 缺 min/max，旧代码还计算 `(undefined+undefined)/2`。点击分组按钮才会走新版 renderMixerStrips，所以“第一次全部挤在一起，点击后又不同”有明确原因。

- [ ] 删除旧版重复声明，仅保留一个读取/渲染/保存入口，增加重复声明静态检查。
- [ ] 读取完成后调用同一个按 section/type 渲染的函数；空分组、读取失败各有明确状态。
- [ ] toggle/select/number 控件与元数据一致；不能把布尔值、枚举转 Number 写回。

### M02：默认值和参数目标不可信

`main.ts:407` 的元数据描述主叙事 temperature，但操作 providers[0]，该 provider 未必是实际主叙事路由。未配置值在 renderer 显示中位数、toggle 显示 OFF、select 显示首项，这些都不代表核心实际默认值。

- [ ] UI 区分“继承默认”“显式配置”“已保存待重载”“运行中有效值”。
- [ ] 从兼容当前核心版本的 schema/解析结果获得默认值；未知时显示未指定，不伪造中位运行值。
- [ ] 主模型参数显式指向当前路由 provider，或选择目标并显示 ID；不要以数组第一个代替路由。
- [ ] 后端 toggle 校验 boolean，select 校验 options 白名单；目前 main.ts:487 后的非 knob 分支直接 apply raw。
- [ ] 保存反馈区分“写入 canonical”和“Worker 已生效”。

### M03：草稿、切组与保存竞态

`app.js:1695` 渲染读 param.value，未叠加 pending；切组会显示旧值。pending 是全局对象，切故事清空，异步加载没有严格故事/视图令牌；写成功直接清空全部 pending，会清掉请求过程中产生的新编辑。立即点重载也可能赶在800ms写入之前。

- [ ] 按 storyId 保存草稿，读请求带序号，过期响应不得渲染到当前故事。
- [ ] 控件显示 pending[key] 优先，切组不丢草稿；保存确认只清本次提交且未再次改变的字段。
- [ ] 同故事保存串行化，失败保留草稿；提供应用/撤销入口，或至少明确自动保存状态。
- [ ] 重载先等待保存队列成功，失败时停在可修正状态；不让按钮与延迟写入比赛。

### M04：布局重整

`style.css:79` 的 flex:1 仍继承到后面的 `.mixer-channel`，后加 width92 并没有清掉旧 flex。45 个参数在旧入口下全部铺开，9px 标签、60px 推子也缺乏读数和单位层级。

- [ ] 使用分组导航+可滚动内容；基础组优先显示常用参数，高级项折叠。
- [ ] 使用显式 Grid 卡片列宽，例如 minmax(160px,1fr)，容器不足时减少列数；具体尺寸通过实际窗口验证。
- [ ] 每项依次显示名称、当前值/单位、控件、简短说明；数字可精确输入，推子只作为辅助。
- [ ] 开关和枚举不占与长推子相同的固定高度；错误/未保存状态保持在该参数附近。
- [ ] 不在每个刷新重建输入控件，保留焦点、编辑文本和选中区间。
