# typ-0 体验改造方案（2026-09-14）

> 核心原则：**不扩充功能数量，把"连接→配模→建角→首聊→调行为→自救"做成一条顺畅路径。**
> 保留轨道工作台特色和剧本架构，不重做三套程序。

---

## 总体架构：三种任务模式

```
┌─────────────────────────────────────────────────────────┐
│  模式切换（顶栏常驻，空格只控制历史回放，不再轮换运行状态）  │
├─────────────┬─────────────┬─────────────────────────────┤
│  🏠 日常     │  🎛 剧本工作台 │  🔍 诊断                    │
│  普通用户默认 │  时间轴/轨道  │  链路/日志/用量              │
└─────────────┴─────────────┴─────────────────────────────┘
```

| 模式 | 默认重点 | 对应当前界面 |
|---|---|---|
| **日常** | 最新对话、当前生活摘要、连接状态、常用操作 | Session + Overview 合并 |
| **剧本工作台** | 时间轴、轨道、原文、分支、事实 | 当前 Studio 主界面 |
| **诊断** | 收发链路、日志、模型用量、有效配置 | Logs + Stats + Koishi 合并 |

**不重做三套程序**——同一套渲染引擎，三种模式只是不同的默认视图和面板组合。

---

## P0-1：连接与账号中心（补齐 SnowLuma 路径）

### 目标
普通用户不读源码、不手改 YAML，也能完成从 0 到首聊的全流程。

### 新增一级入口「连接」

```
连接与账号
├── 📱 连接方式选择
│   ├── SnowLuma（自动检测，推荐）
│   │   ├── 检测状态：未安装 / 已安装未启动 / 已运行
│   │   ├── 登录引导：扫码或密码 → 确认登录账号
│   │   └── WS 地址自动填充（从 SnowLuma 读取）
│   └── 通用 OneBot（手动填写，高级）
│       ├── WS 地址 / Token
│       └── 测试连接
├── 🔗 绑定角色
│   ├── 选择剧本 / 新建
│   └── 机器人 QQ 自动填入（从已连接的渠道读取）
├── 👤 交往对象
│   ├── 白名单管理（添加/移除 QQ 号）
│   └── 测试：向指定 QQ 发送验证消息
└── ✅ 就绪检查
    ├── 渠道已连接 ✓/✗
    ├── 模型可用 ✓/✗
    ├── 白名单非空 ✓/✗
    ├── 首条消息收发测试 [执行]
    └── 状态摘要：尚未就绪——QQ 渠道未连接
```

### 实现要点

| 项 | 方案 |
|---|---|
| SnowLuma 检测 | 主进程扫描进程列表/已知安装路径，返回状态 |
| WS 地址自动填充 | SnowLuma 启动后从其配置文件或 CLI 读取 |
| 就绪检查 | 汇总 channel.connected + narrator.available + 白名单非空 + 最近投递结果 |
| 测试发送 | 用户明确确认后发一条固定消息到指定 QQ |

### 改动文件
- `src/main/main.ts`：新增 `connection:*` IPC handler
- `src/renderer/app.js`：新增 `renderConnectionView()` 
- `src/renderer/index.html`：顶栏加「连接」入口 + 视图容器

## P0-2：首次使用向导 + 就绪检查

### 目标
"存档已创建"和"已经可以聊天"是两个不同状态。向导在两者之间搭桥。

### 新建剧本向导流程

```
步骤 1/5：角色是谁
  → 主角名称、性格简述、世界观
  → （存档 ID 自动生成，放入高级折叠）

步骤 2/5：谁负责生成剧本
  → 从已配置的模型连接中选择，或跳转配置
  → 显示连接测试结果

步骤 3/5：通过哪个账号联系
  → 从已连接的渠道中选择（引导跳转「连接」页）
  → 或标记"稍后配置"

步骤 4/5：谁可以和角色聊天
  → 添加交往对象 QQ 号（白名单）
  → 或选择"允许所有人"

步骤 5/5：启动验证
  → 自动执行就绪检查
  → 显示清单：缺什么、去哪里补
  → 全部通过 → 「开始首聊」按钮
```

### 新建后的进度面板（替代当前"创建完回到工作台什么都不说"）

```
┌─ 剧本「水濑」设置进度 ──────────────────────┐
│ ✅ 人物：已配置                              │
│ ✅ 模型：yunwu/gemini-3-flash 可用           │
│ ⬜ 渠道：未连接 → [去配置连接]               │
│ ⬜ 交往对象：白名单为空 → [添加]             │
│ ⬜ 启动验证：待完成                           │
│                                              │
│ 当前状态：尚未就绪（缺 2 项）                 │
└──────────────────────────────────────────────┘
```

### 改动文件
- `src/renderer/app.js`：新建流程改为多步向导 + `renderSetupProgress()`
- `src/renderer/index.html`：向导容器

## P1-1：统一设置导航 + 全局功能搜索

### 设置导航（替代当前四套分散入口）

```
设置
├── 人物与故事（主角设定、世界观、配角、补充事实）
├── 连接与聊天对象（渠道、白名单、群聊规则）
├── 模型与费用（模型连接、温度、Token 上限、费用显示）
├── 联系节奏（主动联系频率、Urge、休息窗口）
├── 记忆与连续性（事实数量、压缩阈值、回忆深度）
├── 扩展能力（贴纸、表情、网页浏览、多关系）
```

Mixer 保留为快捷调参视图，但每项旁加「→ 完整设置」链接。Koishi 保留为高级入口。

## P1-2：行为预设 + 有效值/来源显示

### 两层配置

**普通层（行为意图预设）**

| 维度 | 选项 |
|---|---|
| 联系频率 | 较少 / 适中 / 较频繁 |
| 费用优先 | 节省 / 均衡 / 保留更多上下文 |
| 聊天范围 | 只私聊 / 允许指定群聊 |
| 日志密度 | 标准 / 诊断 |

每个预设展开显示会改哪些字段和预计影响，不包装"更拟真"。

**高级层（对应真实参数）**

当前 Mixer 的 47 项参数，按设置导航的分组重新组织。

### 有效值显示（替代"未指定（继承）"）

```
┌─ 联系节奏 ─────────────────────────────────┐
│ 自动推进间隔                                 │
│ 正在生效：40 分钟（来源：核心默认）           │
│ 待保存：60 分钟                              │
│ [恢复默认] [撤销本项修改]                    │
│                                             │
│ 页面状态：3 项待保存  [全部保存] [撤销全部]   │
└─────────────────────────────────────────────┘
```

每项区分三种状态：`正在生效值 / 来源（默认/配置/继承） / 待保存修改`。

### 改动文件
- `src/renderer/app.js`：Mixer 改为双层 + 有效值查询链路
- `src/main/main.ts`：暴露 config resolution（合并后的实际值）

## P1-3：操作现场反馈 + 待重载状态

### 原则
日志是详情入口，不是所有失败的唯一通知方式。

### 实现方案

| 场景 | 当前行为 | 改为 |
|---|---|---|
| 加载 Worker 失败 | appendLog | 按钮旁红色提示 + [查看详情] 跳日志 |
| 创建剧本成功 | appendLog | 向导自动进入下一步 |
| 保存配置失败 | appendLog | 保存按钮旁错误 + [重试] |
| 配置已保存待重载 | 无提示 | 顶栏黄色横幅"配置已保存，重载后生效 [重载] [稍后]" |

### 改动文件
- `src/renderer/app.js`：全局 toast/banner 系统 + 操作反馈绑定

## P2-2：视觉层级 + 运行控制重整

### 运行控制

```
当前：▶ / ◐ / ■ 按钮组（空格轮换三态）
改为：
┌──────────────────────────────────────┐
│ 角色：● 运行中    [暂停] [静音]       │
│ 暂停 = 停止自动推进，已收到消息继续处理 │
│ 静音 = 生成剧本但不发送消息（仍消耗 Token）│
└──────────────────────────────────────┘
```

空格键只控制**历史回放**（时间轴播放/暂停），不再影响角色运行状态。运行控制用文字常驻显示。

### 视觉层级

| 项 | 改动 |
|---|---|
| 中文字号 | 正文/表单 ≥13px；辅助 ≥11px；紧凑模式可选 |
| 强调色 | 只用于当前选择、主要操作、异常状态 |
| 技术细节 | 协议版本、artifact hash 等折叠到「技术详情」 |
| 中英文 | 中文任务名为主，英文术语括注 |

## 不做的事

- 不改成聊天软件外观（保留轨道/时间轴特色）
- 不放弃 Koishi 嵌入（保留为高级入口）
- 不重做三套独立程序（同一渲染引擎，三种面板组合）
- 不把"更拟真"包装成预设按钮（预设只改行为参数，不偷偷开功能）
- 不增加新的功能数量（只重组现有功能的入口和呈现）
