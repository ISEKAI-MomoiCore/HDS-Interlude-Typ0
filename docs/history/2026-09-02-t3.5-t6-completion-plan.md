## 2. 不可变的工程约束

1. HDSI 仍是叙事、记忆、事实、场景、Preplan 和角色时间的唯一权威。
2. typ-0 Renderer 不读取或写入 HDSI SQLite，不读取密钥，不持有外部渠道权限。
3. Main Process 是日志、配置、Worker 生命周期、渠道路由和宿主级数据的唯一写入边界。
4. 任何显示用时间估计都不能回写为故事事实；Script 视觉范围尤其如此。
5. 同一渠道账号只可绑定一个故事；静音、暂停、重放与投递确认的既有语义不得因性能优化改变。
6. Blind/失明模式必须最终跨 Studio、Logs、Koishi 一致生效；没有统一屏蔽前，不可声称桌面端支持 Blind。

## 3. 实施顺序

```text
M1 LogBroker
  └─ M2 宿主 Projection API / 关联 ID
       ├─ M3 范围化 HDSI Timeline Projection
       │    └─ M4 Arrangement 缩放、LOD 与稳定 SelectionContext
       └─ M5 Logs Surface 完成版
            └─ M6 Koishi Console 隔离 Surface
                 └─ M7 一个真实渠道私聊纯文本闭环
                      └─ M8 T5 普通用户配置中心与发布准备
```

每个 Milestone 可以独立测试；后一个阶段不能绕开前一个阶段直接在 Renderer 中复制业务逻辑。

## M1：主进程 LogBroker（已完成）

### 目标

将当前零散的 `story:log` 文本升级为宿主级 `DesktopLogRecord`：保留原文、分配稳定 ID、按故事隔离、有限内存缓存、异步按日落盘，并允许 Renderer 以游标/筛选方式读取。

### 数据契约

```ts
interface DesktopLogRecord {
  id: string
  at: string                 // 事件被宿主记录的 ISO 时间
  storyId?: string           // 空表示桌面全局日志
  level: 'debug' | 'info' | 'warn' | 'error'
  source: 'desktop' | 'worker' | 'bridge' | 'router' | 'delivery' | 'channel' | 'koishi'
  logger?: string
  message: string            // 完整原文，不在落盘阶段截断
  correlation?: {
    requestId?: string
    inboundId?: string
    deliveryId?: string
    entityId?: string
  }
}
```

### 实现边界

- 采用 `dataRoot/logs/<story-or-desktop>/YYYY-MM-DD.ndjson`。
- 写入采用批量异步队列，不在消息路由或 Worker stdout 回调中进行同步磁盘 I/O。
- 内存环形缓冲有固定上限；淘汰内存副本不影响已排队或已落盘记录。
- 初版查询支持 `storyId`、时间范围、level、source、logger、关键词、correlation ID、limit、before cursor。
- 现有 `story:log` 保持兼容；Main Process 将其镜像为 `logs:record`。
- 初版不做全文索引、跨日大文件检索线程、日志导出或 Blind 内容过滤；这些必须在 M5 建立。

### 验收

1. Worker stdout/stderr、bridge、router、delivery、桌面异常都得到稳定记录 ID；
2. 一条日志同时能在兼容 `story:log` 和新 `logs:record` 看到，但 Renderer 不重复显示；
3. 进程不等待磁盘写入即可继续路由消息；
4. 重启后可从当天 NDJSON 查询最近记录；
5. 单元测试覆盖：环形上限、故事隔离、筛选、异步落盘、原文保留。

### 本轮落地记录（2026-09-02）

- 新增 `desktop/src/main/runtime/log-broker.ts`：有限内存环形缓冲、250ms 异步微批、`logs/<story-or-desktop>/YYYY-MM-DD.ndjson` 落盘、按故事/时间/等级/来源/关键词/游标的只读查询；损坏或不完整的 NDJSON 单行会被隔离跳过。
- Main Process 继续发送旧 `story:log` 兼容事件，同时镜像为 `logs:record`。Worker、bridge、router、delivery、桌面流程的来源由宿主前缀归类；投递记录附带 `deliveryId` correlation。
- Renderer 订阅新的记录流并在故事切换/启动后从持久化查询补齐，避免与旧事件重复显示；“清屏”只清当前视图。
- 验证：`npm run typecheck`、`npm run test:runtime`（13 项）、`npm run build` 均通过。
- 有意留到 M5：多日大日志的后台检索、保留/轮转策略、导出、复杂 correlation 深链、Blind 内容规则和虚拟化滚动。

## M2：宿主 Projection 与关联模型（已完成）

### 目标

统一故事、Inbox、Outbox、Worker 资源、日志、用量的只读投影，并在 delivery、inbound、request、timeline entity 之间传递 correlation ID。

### 必做

- `getStoryOverview({ storyId })`：phase、Worker、inbox size、Outbox 摘要、最近错误、当日用量；
- `getDeliveryHistory({ storyId, cursor })`：读取持久 Outbox，不局限本次 Renderer 会话；
- `getUsageSeries({ storyId, from, to, granularity })`：读取 UsageAggregator；
- 日志可由 `deliveryId`、`requestId`、`entityId` 反向定位；
- 所有输出带 `storyId`、`source`、记录时间和稳定 ID。

### 本轮落地记录（2026-09-02）

- 新增 `desktop/src/main/runtime/host-projection.ts`。`overview(storyId)` 只汇总 typ-0 自己拥有的 Worker、Inbox、Outbox、用量与 LogBroker 错误；不读取 HDSI SQLite、不暴露密钥，也没有任意文件读取能力。
- `DeliveryOutbox` 增加 newest-first 的持久历史游标读取及状态摘要；`UsageAggregator` 增加按故事、日期范围的只读日粒度序列。IPC 以 `runtime:overview`、`stories:deliveries`、`stories:usage` 暴露给受限 preload。
- Studio Inspector 现在显示持久 Inbox/Outbox/用量摘要及最近错误；Deliveries 与 Model Usage Detail 可在桌面重启后读取历史，不再只依赖当前 Renderer 会话的增量事件。
- 已建立 delivery error → `deliveryId` correlation 的首条闭环。request、inbound 与 timeline entity 的完整关联将在 M3 的版本化 Timeline Projection 中补齐。
- 验证：`npm run typecheck`、`npm run test:runtime`（14 项）、`node --check src/renderer/app.js`、`npm run build` 均通过。

### 不做

- 不向 Renderer 暴露通用文件读写；
- 不让 Main Process 解读 HDSI 业务表；
- 不把 HDSI 事件时间与桌面接收时间混为一谈。

## M3：范围化 HDSI Timeline Projection（已完成）

### 目标

用版本化查询取代固定 snapshot，支持 Arrangement 视口加载与真实 Script 覆盖区间。

### HDSI bridge 扩展

```ts
getTimelineRange({ from, to, tracks, cursor, detailLevel })
subscribeStoryEvents({ afterRevision })
```

### 必做

- `revision` 单调递增，断裂时要求完整范围重取；
- timeline item 具有稳定 ID、轨道、occurredAt、可选 endedAt、摘要和关联对象；
- HDSI 直接提供 Script 或自动推进覆盖区间，删除前端文本长度估时；
- 默认只取视口范围和小缓冲。

### 本轮落地记录（2026-09-02）

- HDSI bridge 新增只读 `timeline-range` 命令；服务端 `desktopTimelineRange()` 接受 `from/to/tracks/cursor/detailLevel/limit`，范围最大 14 天、单次最多 500 条，避免 GUI 意外拉取全库。
- 返回对象提供协议版本、范围专属 opaque revision、稳定 `entityId`、轨道、可选 `nextCursor`。桌面主进程会再次规范化 IPC 字段，Renderer 不会获得 HDSI 数据库或未知 metadata。
- 自动推进、对话余波和到期承诺等已经拥有时间导演账本的新增 Script 条目会同步保存 `timelineWindow {from,to}`；Arrangement 直接以它画真实覆盖块。没有该字段的旧历史、普通用户回合仍是时间点，**不再用文本长度推断生活时长**。
- 原有 `snapshot` 与 bridge protocol 2 保持兼容；新增 range 能力声明为 protocol 3。遇到预 M3 的 v2 worker，桌面端会立即退回兼容快照而非等待未知命令超时；v3 才走范围投影。
- 冲突检查：没有改变 HDSI 的 cursor、故事时间、记忆、Preplan 或写入权限；范围只读查询在 HDSI 自己的 live SQLite 连接中执行。主仓库构建入口为 `C:\dev\HDS-Interlude`，插件子目录没有独立 build script。
- 验证：HDSI `typecheck`、136 项测试与根仓库 build 通过；桌面端 `typecheck`、15 项 runtime 测试、Renderer 语法检查与 build 通过。

## M4：Arrangement 与 SelectionContext 完成版

### 本轮落地记录（2026-09-02）

- Renderer 的 `WorkspaceState` 现按故事保存时间窗、五条轨道显示状态和 Browser / Inspector / Detail 的面板可见性；存储内容仅是本机 UI 偏好，绝不写入 HDSI、Koishi 配置或故事数据库。
- Arrangement 使用范围 Projection 的真实 `from/to` 作为可缩放视口：`− / ＋` 缩放、`‹ / ›` 平移、`NOW` 返回跟随模式已经可用；Ctrl/⌘ + 滚轮缩放，Shift + 滚轮横向平移。连续滚轮操作以短防抖合并，避免向 Worker 发送密集范围查询。
- Browser 改为可折叠的多级菜单：故事视图、Arrangement 轨道、故事操作分别独立收纳；轨道菜单展示当前范围的对象计数并可显隐 Script、Timeline、Receive/Send、Facts & Scenes、Preplan。Facts/Scenes 与 Schedule 的专用视图不受主 Arrangement 显隐影响。
- Script 块保留 HDSI 提供的真实覆盖区间；块内新增条目数量和 `RANGE / POINT` 标记，仍不会依据文本长度推测持续时间。轨道的粘性标签、固定标尺、网格和紧凑高度提高了窄屏阅读时的信息密度。
- 选中对象现在持久化为稳定的 `storyId + entityId + type`，范围刷新后会重新定位；对象不在新范围内时自动退回故事状态，清除旧的 Script 展开引用，不保留指向过期快照的 UI 对象。
- 面板可由各自标题栏收起；任一面板被收起后仍可从顶栏 `Layout` 菜单恢复。M4 不做自由拖拽分栏和像素级尺寸持久化，先保持布局确定、键鼠可达且不引入额外窗口状态复杂度。

### 验收与剩余边界

- 已完成：有界范围读取、缩放/平移/Now、轨道开关、每故事布局、稳定选择恢复、失效选择清理、面板收起/恢复。
- 延后：按 1k/10k/100k 项的虚拟化或 Canvas LOD 基准；当前 HDSI range API 本身限制单次最多 500 条，M4 的 DOM 量因此可控。超过该边界前不提前引入 Canvas 双渲染器。
- 延后：可拖拽调整左右/下方面板尺寸。它需要统一 Pointer Capture、最小尺寸与高 DPI 复原策略，应与后续 Dock Layout 一并实现，不能用临时 CSS 把状态写散。

### 必做

- ✅ 水平平移、缩放、回到 Now、轨道显示开关；
- ✅ 可序列化 `storyId / surface / timeRange / selected entity / layout`；筛选器待 M5 Logs 统一接入；
- 🟡 面板折叠、每故事布局持久化；自由尺寸调整延后到 Dock Layout；
- ⬜ 可视区域虚拟化或 Canvas 绘制，建立 1k / 10k / 100k item 基准；
- ✅ 选中失效时退回故事状态、清理过期选择；
- ✅ 过去/现在/未来与处理/投递时间以范围标尺和分轨呈现。

## 4. 文档维护规则

原设计文档的每个阶段标题下都应以状态标记维护：

- `✅ 已完成`：有代码、自动测试与至少一次对应验收；
- `🟡 部分完成`：明确列出已落地子项和仍缺子项；
- `⬜ 未开始`：仅保留设计和依赖；
- `⛔ 不做`：标明为何不在当前阶段实现。

不要再保留“10 项测试”这类会过时的自由文本；测试数量应以当前自动化命令结果或链接到测试文件为准。
