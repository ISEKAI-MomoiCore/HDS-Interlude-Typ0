# typ-0 Studio 界面审计与修复实施方案

日期：2026-09-09。范围：主播放器 / Arrangement、剧本预览和全文阅读、缩放与面板、时间轴与拖拉条，以及影响这些界面的宿主投影、Console、Logs、Session、Mixer。

本次只新增此文档，不修改源码、构建产物、配置、数据库，不启动或重启故事。本报告依据用户截图、当前源码、设计文档和只读的函数级检查。没有执行真实窗口的完整交互回归；需要窗口测量的项目明确列入验收，不将静态推断写成实机通过。

## 1. 结论与证据基线

当前主要问题是界面内部缺少统一的布局、时间视窗和交互状态管理。多轮局部修复留下了互相覆盖的 CSS、失效的启动绑定、不同坐标系的更新函数。继续逐项调整 margin、百分比或 z-index，会让一种窗口尺寸正常、另一种操作组合重新失效。

要实现 FL Studio / 钢琴窗式工作台，建议保留现有宿主与 HDSI 桥接，把前端整理成一个共享时间视窗的多轨观察器：轨道块的水平长度表达时间，垂直空间与详情阅读表达文字量，鼠标动作统一转换为时间。历史剧本仍是来源文本，拖动观察视窗不会改写历史。

| UI-37 / P1 | `app.js:1132,1133`；`index.html` 两个 dialog | cancel 按钮默认 submit；submit handler 无 submitter 判断，preventDefault 后照样创建/保存；表现为取消变保存或被表单校验卡住 | 取消 type=button 显式 close，提交独立；禁用重复提交，保留错误与焦点 |

## 3. 为什么前几轮“验证通过”仍会出现这些问题

`DESKTOP-DESIGN.md` 记录的 renderer 语法检查能证明 JS 可解析，但缺 DOM 的 addEventListener 也是合法 JS。后端 runtime 测试主要证明宿主、投递或数据机制，不能证明像素对齐或首次加载完成。

当前文档与源码还存在明确差异：

- 10.29 写快照前后各扩 15%，当前 `refreshSnapshot()` 直接传 viewport.from/to；写 end 至少 NOW+5min，当前 ranged 分支直接返回原 range。
- 10.22 写自定义面板尺寸重启恢复，但 applyPanelLayout 不读取 panelWidths/panelHeights；恢复条被 CSS 隐藏。
- 10.26 对“底部定时器不可靠”的解释缺乏当前源码支持：UI-01 的同步异常足以使后续注册没有执行，应先修启动流程后重新验证，不能归因于 Electron 天生不执行底部定时器。
- “左侧起点对齐 diff=0”不能证明时间轴对齐；还要测 25%、50%、75%、100%，以及面板改变和横向滚动后的同一时间点。

后续每次验证应记录 UI 源码/产物指纹、启动方式、视口与 zoom、测试动作和测量结果。历史记录保留，新增“已被后续方案替代”指引，避免把不同轮次互相冲突的实现同时当成规范。

## 4. 目标架构：可渐进实现的钢琴窗式工作台

### 4.1 清晰分配时间和阅读空间

主区建议采用 `工具栏 → 时间标尺 → 多轨道画布 → 总览拖拉条`。左侧轨道头固定宽度，右侧 Inspector 显示选中对象，下方 Detail 阅读完整原文。

剧本长度自适应分三件事：

1. **水平跨度**由确认的开始/结束时间决定；点事件和推断保持区间另有视觉样式。文字多不代表时间长。
2. **预览容量**由实际像素决定。小块显示标识或色块，中块显示摘要，大块显示更多原文；用户可以调 Script 轨高，预览随高度展开。不要生成新的模型摘要来解决 UI 问题。
3. **全文阅读**由 Detail 自适应换行、保留段落、独立滚动承担。选择后可临时扩大阅读区或最大化，返回时保留时间轴位置；不要求轨道块无限增高。

在很密集的点事件上，视觉对象可显示 `3 messages` 聚合块，点击后列出三条原始事件。聚合有清晰的数量和范围，放大后分离；投递状态、来源身份仍跟各原始条目走。

### 4.2 最小模块拆分

| 建议模块 | 负责什么 | 不应再由谁重复处理 |
| --- | --- | --- |
| `workspace-state` | 故事、Surface、Tab、布局尺寸与存储迁移 | 各个 DOM 回调各自改内联模板 |
| `timeline-viewport` | viewRange、follow、缩放锚点、x↔time | ruler、playhead、purge 各自写公式 |
| `timeline-data` | 数据范围、分页、缓存、前驱锚点、revision、加载缺口 | renderArrangement 同时查询和推断完整历史 |
| `timeline-layout` | 区间裁剪、子行避让、聚合、刻度、预览等级 | clip 函数临时钳位百分比掩盖问题 |
| `timeline-interaction` | pan、zoom、选择、pointer capture、取消 | 旧/新两套 scroller 监听与 Shift 删除混合 |
| `timeline-view` / `script-reader` | 稳定 DOM 绘制和全文阅读 | 每次宿主状态刷新重建整页 |
| `console-surface` / `log-view` | 嵌入生命周期与日志展示 | 主时间轴渲染顺带接管原生视图 |

可以先保持原生 JS 和 DOM。当前每页数百事件足以先用稳定 DOM + 可视区过滤；是否切 Canvas 由远景聚合后的实测性能决定。换框架或 Canvas 不会自动解决时间语义和坐标错误。

### 4.3 共用几何规则

令可见时间范围为 `[t0,t1]`，可见轨道绘制宽度为 `W`，轨道画布左边界为 `L`：

```text
x(t) = L + (t - t0) / (t1 - t0) * W
t(x) = t0 + (x - L) / W * (t1 - t0)
```

若选择内容坐标滚动模型，滚动量只在 viewport 模块里转换一次。其它组件不得再补 132px、192px 或另一种比例。时间段先做相交检测再裁剪，真实结束与视觉截断是两个字段。

滚轮锚定位置比例为 u 时，新跨度 S' 的左端是 `anchorTime - u*S'`。拖动左手柄先保持右端，再夹左端；右手柄反之。总览拖拉条使用独立且手势期间冻结的总范围。

NOW、阅读游标、引擎状态分别显示：NOW 是墙钟；点击查看过去只改变阅读定位；▶/暂停控制故事运行。按播放器习惯设计手感，但查看旧剧本不应该隐含触发重跑、分支或删除。

### 4.4 图层与交互约定

- 轨道背景/格线 → 内容块 → 选中描边 → 时间线覆盖层 → 手势提示 → 菜单/对话框。层级集中定义；overlay 裁剪到画布。
- 默认滚轮纵向滚轨；横向滚轮/Shift+滚轮平移；Ctrl+滚轮围绕鼠标缩放；提供 NOW 与 Fit 控制和可发现的快捷键提示。
- 框选只产生选区，Escape 取消；删除走独立入口和范围确认。历史块默认不能改变原始时间，后续若支持可编辑 Preplan，也应有独立权限和样式。
- 不做“高频运动就每个事件落盘”：pointermove 每帧合并绘制，pointerup 或短暂空闲后保存布局，数据请求单独合并。
- 字号和应用缩放独立于时间缩放。缩放后重新测量轨道区域；Console 原生矩形须做专门映射与实测。

## 6. 验收矩阵：必须验证组合，不能只验证单个按钮

### 6.1 测试数据

建立隔离 fixtures，不用生产故事做删除、分支或反复写入测试：

- 空故事、单一短段、单一 8,000 字段落、混合中文/英文/emoji/长 URL/多段换行。
- 1 分钟内 50 条 receive/send、同毫秒多条、相互重叠区间、零长度点。
- 两段之间 12 小时空档、暂停后数日重开、跨午夜、旧记录无 endedAt、确认时间段覆盖整个视窗。
- 左/右边界各有相交段和完全窗外段；跨窗段开始时间远于 15% 扩展范围。
- 超 240/500 条窗口、分页和慢请求、查询失败后恢复、快速切故事。
- 历史工作区含旧 tracks 键、非法跨度、合法 60 天前视窗、面板尺寸大于当前窗口。
- 含 ANSI 的多行日志；未确认/失败/成功多气泡投递；Mixer 读写期间切故事。

### 6.2 窗口和交互

| 场景 | 验收要求 |
| --- | --- |
| 首次载入和重启 | 使用构建后的入口；未捕获异常为 0，所有核心监听生效，不依赖 DevTools 手动 refresh |
| 1440×900、1280×720、1024×768；产品若支持更小窗口则加测 | 工作区和主要操作不被 body hidden 裁掉；不足空间时按紧凑策略降级 |
| 系统缩放 100/125/150/200%；应用 zoom 80/100/125/150% | 标尺和轨道仍对齐；字号可读，菜单/Console 边界正确；区分 CSS px 与物理像素 |
| 左右栏同时拖到极限，Detail 拉高，随后缩小窗口 | 中间画布保有约定最小尺寸；手柄和恢复按钮可达；无隐式 grid 列 |
| 全部面板折叠组合，跨故事，重启 | 内联布局不压过折叠状态；尺寸与显隐按所选存储策略恢复 |
| 15 分钟到两周缩放，再回 NOW | 连续变化、锚点≤1 CSS px误差；跨日刻度不歧义；点事件变聚合而非叠成乱码 |
| 拖拉条左右柄达到最小/最大跨度并继续拖 | 非拖动端稳定；无反向、跳跃、捕获丢失；松开/取消后状态一致 |
| 拖动中到达新快照，回看时收到消息 | 手势优先，回看不被强制拉 NOW；有新内容提示 |
| 选中长剧本后到来 token/delivery 事件 | 全文滚动与文字选择保留；选中样式、Inspector、Detail 指向同一 ID |
| Session/Mixer/空故事/Worker 停止 | 旧轨道 NOW 与拖拉条不留在不相关视图上 |
| Koishi→Studio→Logs，切故事、开对话框、调面板 | 原生 Console 不遮挡旧区域、不保留前故事画面；anchor 矩形随布局更新 |
| Shift 框选后在画布外松开、Escape、右键 | 不残留选区，不自动删记录，不触发其它 clip 动作 |
| Logs 连续每秒追加 1 条，暂停、筛选、加载历史 | 内容与计数一致；无“计数增加但行不出现”；跟随和回看均正确 |
| 新建/配置弹窗取消与关闭 | 不创建、不保存；提交一次只发一次请求 |

### 6.3 性能与正确性目标

- 本地 fixture 拖动/缩放以 60fps 为目标，记录帧时间与主线程长任务；持续手势中不反复全量创建数百 clip。
- 拖动期间不每事件同步写 localStorage；范围请求合并，同故事同视窗不并行重复取数。
- 长历史远景先聚合并标记覆盖，局部放大再取细节；不能为保持帧率静默丢条目。
- 一小时运行观察 DOM 节点/监听数量、刷新次数与内存趋势；隐藏窗口/Surface 停止无用动画绘制。
- UI 验收前后核对原始条目 ID、正文、时间与投递状态，确认布局没有反写剧情数据。

## 7. 本次交付边界与下一步

本报告列出 37 组确定缺陷和组合风险，覆盖当前单文件 renderer 的主要渲染及交互入口，并追到宿主时间线归一化、已安装核心范围过滤及 Console 原生视图边界。它不是“所有设备上所有视觉问题已经复现”的声明。

下一步建议先实施 R0+R1，再一起做 R2。优先验收冷启动和统一几何，而不是把截图中的粉色框单独放大。R2 完成后，再做 R3 的面积驱动预览与密集事件布局，才会接近可持续使用的 FL Studio / 钢琴窗工作台。
