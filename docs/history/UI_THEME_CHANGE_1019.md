## 二、全局“设计感”问题

### 1. 字号层级没有拉开，核心内容反而太小

实测默认清澄主题、工作台密度下：

| 内容 | 当前 | 问题 |
|---|---:|---|
| 工作区标题 | 约 13px | 与按钮、栏目标题差距不明显 |
| 当前场景标题 | **14px** | 参考稿相同位置约 **19px**，当前缺少视觉焦点 |
| 持续性事实正文 | **10px** | 核心故事内容被当作元信息处理 |
| Inspector 字段名 | 约 9px | 长时间阅读吃力 |
| 部分编号、辅助标记 | 7–8px | 容易变成视觉噪声，而非有效信息 |

建议不是把所有字一起放大，而是拉开职责：**场景标题、阅读正文、元信息、技术字段四个等级。**

### 2. 中文字体与等宽字体混用不够受控

在本次渲染环境中，Events 等详情行的拉丁字符使用 Consolas，中文回退到了 **NSimSun（新宋体）**；主界面则使用 Noto Sans SC。

这会让同一界面出现“现代无衬线 UI”和“终端式宋体中文”混杂的感觉。时间、ID、Token 可以等宽，中文正文和说明不应该整体套等宽栈。

### 3. 间距没有充分表达分组关系

目前经常是：
- 组内字段挨得很紧；
- 组与组之间也差不多紧；
- 外层再加一圈边框；
- 内容少时又留下与结构无关的大空白。

缺少明确的“组内紧、组间松”。应统一间距节奏，而不是逐个组件补零碎的 margin。

### 4. 边框和小标签过多，信息权重过于平均

卡片、状态块、栏目、输入框、列表行都在用相近的细线和小字表达自己。结果是每个东西都“有设计”，但整页没有主角。

参考稿值得借鉴的是**构图和阅读顺序**，不是继续增加边框、英文小字或装饰性编号。

### 5. 同一信息反复出现，消耗有效空间

故事状态、场景、事实、用量同时出现在顶部、总览、右侧 Inspector 和底部详情。

这让界面显得复杂，但并没有等比例增加信息价值。尤其 Connect、Logs、Console 不应该默认背着完整 Studio 工作台的全部附属面板。

### 6. 导航语言和图标体系不统一

存在：
- 中文＋英文副标题；
- 纯英文；
- 技术缩写；
- `ANALYSIS Analysis`、`CONFIG Configure` 这类近似占位文本的写法；
- 不同字形符号充当图标，尺寸和基线不统一。

这些小问题叠加后，会削弱成品感。

## 五、配置弹窗：八个标签

**公共问题：切换标签时弹窗明显跳动。**  
1440×1000 下，人设页约 783px 高，白名单／密钥页约 503px，YAML 页约 698px。标题和操作按钮跟着上下移动；短页面则留下一大块空白。

| 标签 | 具体问题 |
|---|---|
| **人设与故事** | 多个长文本域连续堆叠，人设、世界、叙事、用户默认的层级不明显，核心身份字段没有视觉中心。 |

| **机器人** | 小输入框、微型开关、“删”组成一条工具条，缺少清晰的账号身份结构。 |

## 六、弹窗、辅助页和底部详情

### 弹窗与辅助页

- **新建剧本六步**：高度约在 304–448px 间变化，“下一步”位置漂移；标题和正文重复显示步骤数，缺少稳定进度结构。
- **账号接入**：字段之间留白较大，说明文字却很小；切到微信／其他通道后，仍显示“SnowLuma 连接地址”和相关 Token 文案。
- **分支续写**：标题和长说明横向争空间，标题被挤成两行；`forkPoint = entryId` 与主要操作放在同一层级，开发语汇过于外露。
- **外观与主题**：工作台、密度、动效、配色是不同层级的设置，却挤成几排分段按钮；纯色条难以预判实际界面效果。
- **帮助**：快捷键和术语密集，分类与组间留白不足。
- **全局搜索**：空输入状态过于单薄，缺少搜索范围、常用入口和键盘操作提示。

### 底部五个详情标签

- **Script**：专属排版缺失，默认高度也不足以舒适阅读长正文。
- **Events**：消息正文与时间、技术类型同权重，10px 等宽排版不利于中文阅读。
- **Deliveries**：失败原因与普通记录的视觉区分不足，应突出状态、原因和下一步。
- **Model Usage**：`calls/in/cached/out/est` 拼成技术字符串，指标与单位缺少清晰列结构。
- **Data**：原始 JSON 直接铺在底栏，明显偏调试工具；应明确其高级用途，并提供分组、复制等辅助。
