# HDSI Desktop typ·0 UI 设计规范 V5

## 纸面主场：硬光影工作台与 Night Signal 暗色模式

> **状态：** 设计提案，供下一轮前端改造使用；本文件不代表 V5 已实现。  
> **审查日期：** 2026-09-30  
> **设计基准：** V2 信息架构与新手引导、V3 主题系统与纸面极简方向、V4 Overview ↔ Timeline 展开工作台，以及当前 Electron renderer 的 HTML/CSS/JS 实现。  
> **本次修订：** V5 不再以暗色作为默认主题。默认主题回到 V3 参考稿的纸质感工作台；Night Signal 作为同一设计系统的暗色模式。两套模式共享语义、交互和布局，只改变视觉材质与光影表现。

---

## 0. V5 设计结论

V5 的核心不是把 typ·0 做成一套“更炫的后台”，而是把它做成一个**有纸面质感、有明确光源、有硬朗层次、可直接操作的故事编辑工作台**。

默认体验应接近：

- 一张暖白的工作桌面；
- 一叠有层次的纸张、索引卡和章节页；
- 一束方向明确的硬光照在当前工作区；
- 选中的对象像被夹子、色带或描边固定在桌面上；
- 重要操作像纸面上的印章、标签和工具按钮；
- 时间线像一条可移动的编辑胶片，而不是一块平铺的日志表。

暗色模式不是另一套产品，而是同一张工作台在夜间的版本：纸张变为墨蓝黑，硬光变为冷色边缘光，信号橙成为局部照明色，但仍然保留纸张、卡片、夹层、切片和工作台的语义。

### 0.1 V5 一句话

> **默认是“纸面编辑台”，暗色是“夜间编辑台”；夸张来自清晰的硬光影、尺度和材质层次，而不是来自无意义的发光与动画。**

### 0.2 V5 解决的问题

V5 需要同时解决三个问题：

1. **视觉问题：** 当前深灰主题层次较平，亮黄承担了品牌、焦点、选中和主动作过多语义；V3 参考稿中的纸面、靛蓝、苔绿和朱红更有设计感，应回到默认主题。
2. **交互问题：** 当前能力已经很多，但部分操作仍藏在菜单、右键或内部术语中；需要让故事、轨道、端点、投递、日志都能直接继续操作。
3. **材质问题：** 面板之间缺少“叠放关系”。V5 使用有限、可控的硬光影建立层级：谁在桌面上、谁被选中、谁是浮层、谁是被压住的背景，应一眼可见。

### 0.3 V5 不做什么

- 不把所有面板做成厚重卡片。
- 不用大面积渐变、持续呼吸灯或全局霓虹。
- 不用模糊阴影替代真实层级。
- 不让动画承担状态说明。
- 不因为增加视觉元素而减少时间线、日志和诊断信息。
- 不在本轮引入远程主题脚本、任意 CSS 上传或社区主题市场。
- 不凭空增加后端尚未支持的交互按钮。

## 1. 既有设计的继承关系

### 1.1 从 V2 继承：易懂的工作台

继续保留：

- 连接、剧本、诊断、Console 的业务分区；
- Worker、模型、渠道、账号和故事的就绪检查；
- 状态必须同时使用颜色、图标和文字；
- 1280×720 下主要任务可完成；
- YAML/结构化配置的保存、草稿与重载区别；
- 新用户能够知道下一步该做什么。

V5 将“下一步”从 Connect 页面扩展到所有页面。任何空状态、错误状态、待处理状态都要有可执行入口。

### 1.2 从 V3 继承：纸面与主题系统

V3 的参考稿 `C:\dev\typ0-v3-interface.html` 已经提供了适合 typ·0 的视觉基础：

- 暖白纸面；
- 墨色文字；
- 靛蓝、苔绿、朱红和沙金语义色；
- 大章节标题；
- 端点、参与者、路由等 Inspector 信息分区；
- 轻量但有材质感的卡片与列表。

V5 不把纸面风格替换为 Night Signal，而是把它正式定义为**默认主题 `Paper Studio`**。Night Signal 仅作为同一套 token 的暗色变体。

### 1.3 从 V4 继承：同一工作区的展开

继续保留：

```text
Overview
  ↓ 点击预览轨道 / 当前场景 / 时间线
Timeline
```

V5 强化转场前后的视觉连续性：

- Overview 的三条窄轨是纸面上的三条编辑胶片；
- Timeline 展开时，轨道像纸带被向下拉开，而不是切换到另一页；
- 选中事件用硬边夹线和局部阴影标记；
- reduced motion 下直接切换，布局和选择状态不改变。

## 2. 两套官方主题：Paper Studio 与 Night Signal

### 2.1 主题定位

| 主题 | 定位 | 默认场景 | 视觉材料 |
|---|---|---|---|
| `paper-studio` | 默认主题 | 日常写作、配置、阅读、长时间使用 | 暖白纸、墨色、靛蓝、苔绿、朱红、硬投影 |
| `night-signal` | 暗色模式 | 夜间操作、深色环境、诊断和长时间运行观察 | 墨蓝黑纸面、冷灰边缘、信号橙、青色焦点光 |

两套主题共享：

- 颜色语义，不共享具体色值；
- 组件名称和 DOM 结构；
- 键盘操作、焦点规则和状态文本；
- 页面布局和面板职责；
- reduced motion 规则；
- 交互反馈时序。

主题切换只改变材质表现，不改变：

- Worker 状态含义；
- delivery 状态含义；
- 轨道顺序；
- 数据读写边界；
- 控件可用性；
- 高风险操作确认策略。

### 2.4 外观偏好

沿用现有 `hdsi.typ0.workspace` 的 localStorage 持久化，但新增独立的 `appearance` 字段：

```js
appearance: {
  theme: 'paper-studio',      // paper-studio | night-signal
  density: 'comfortable',     // comfortable | compact
  shadowMode: 'hard',         // hard | soft | none
  reduceMotion: 'system'      // system | on | off
}
```

- 新用户默认：`paper-studio` + `comfortable` + `hard`。
- 暗色模式可通过顶栏外观菜单切换，不改变故事或布局状态。
- `shadowMode: soft` 只作为低刺激选项，不作为默认主题；`none` 用于极端性能或高对比环境。
- 无效或旧版本值自动回退，不影响故事状态和配置数据。
- 主题切换应即时预览，不能刷新 Worker，也不能造成故事重载。

## 3. V5 的硬光影系统

### 3.1 “硬光影”是什么

V5 使用的是**硬边、短距离、方向明确、低透明度的投影**，而不是大面积模糊发光。

硬光影主要表达四种关系：

1. **层级：** 浮层、对话框、菜单在纸面上方；
2. **选择：** 当前故事、事件或输入控件被光线切出；
3. **操作：** 按钮按下、拖拽、切换时有明确的几何反馈；
4. **结构：** 时间线、索引卡、标签和轨道有纸带/夹层关系。

硬光影不能用来表示成功或错误；成功/错误仍由语义颜色、图标和文字表达。

### 3.2 光源模型

整个应用只建立三类光源：

- **桌面环境光：** 负责画布和普通面板的基础明度；
- **左上方主光：** 负责浮起纸张、选中卡片和当前工作区的短投影；
- **局部色光：** 只用于当前焦点、NOW 播放头、关键主按钮和错误提示边缘。

光源方向必须统一。默认使用左上向右下：

```text
光源 ↘
纸张 / 卡片
       ▾ 短硬影
```

不能出现一个卡片向左投影、另一个按钮向右投影的混乱现象。

### 3.3 CSS Token

```css
:root {
  --t0-shadow-hard-1: 3px 3px 0 rgba(45, 48, 43, .16);
  --t0-shadow-hard-2: 6px 6px 0 rgba(45, 48, 43, .10);
  --t0-shadow-float: 8px 10px 0 rgba(45, 48, 43, .13);
  --t0-shadow-inset: inset 0 1px 0 rgba(255,255,255,.65), inset 0 -1px 0 rgba(35,39,35,.10);
  --t0-shadow-focus: 4px 4px 0 color-mix(in srgb, var(--t0-focus) 26%, transparent);
  --t0-shadow-dialog: 10px 12px 0 rgba(34, 38, 35, .20);
  --t0-light-edge: rgba(255,255,255,.70);
  --t0-dark-edge: rgba(42,46,41,.18);
}

[data-theme="night-signal"] {
  --t0-shadow-hard-1: 3px 3px 0 rgba(0, 0, 0, .38);
  --t0-shadow-hard-2: 6px 6px 0 rgba(0, 0, 0, .26);
  --t0-shadow-float: 8px 10px 0 rgba(0, 0, 0, .42);
  --t0-shadow-inset: inset 0 1px 0 rgba(255,255,255,.10), inset 0 -1px 0 rgba(0,0,0,.35);
  --t0-shadow-focus: 4px 4px 0 color-mix(in srgb, var(--t0-focus) 30%, transparent);
  --t0-shadow-dialog: 10px 12px 0 rgba(0, 0, 0, .48);
  --t0-light-edge: rgba(255,255,255,.12);
  --t0-dark-edge: rgba(0,0,0,.40);
}
```

如果运行环境不支持 `color-mix()`，实现必须提供静态 fallback。硬影的颜色不应直接写入组件，必须通过 token 引用。

### 3.4 硬光影使用规则

| 对象 | 默认表现 | 说明 |
|---|---|---|
| 普通面板 | 细边线 + 极弱底边 | 不给所有面板都加浮起阴影 |
| 当前故事卡 | 右下短硬影 + 左上亮边 | 表示可选中和当前上下文 |
| 主 CTA | 2px 硬影；按下时影子缩短 | 让按钮有实体感 |
| Popover / Menu | 6–8px 短硬影 | 与页面建立清晰上下层 |
| Dialog | 10px 硬影 + 遮罩 | 不用玻璃模糊作为主要层级 |
| 当前选中对象 | 青色/靛蓝硬边 + 极短色影 | 不依赖发光或闪烁 |
| Timeline NOW | 橙色竖线 + 小三角旗 + 短色影 | 文字、形状和颜色三重编码 |
| Disabled | 不投影、低对比边线 | 禁用控件不应像可点击浮层 |
| Toast | 3px 硬影 | 让其像贴在桌面上的通知纸条 |

### 3.5 光影禁用项

- 不在页面背景使用大型 `box-shadow`；
- 不给每个列表行增加浮起阴影；
- 不使用持续闪烁的 `filter: drop-shadow()`；
- 不用 30px 以上 blur 做主要结构；
- 不使用阴影区分成功和失败；
- 不让阴影导致文字边缘模糊；
- 不让主题作者通过阴影隐藏焦点环和错误信息。

### 3.6 纸面材质

纸质感使用非常轻的静态纹理或 CSS 图案即可：

- 允许低对比度噪点/细点阵；
- 允许局部纸边、索引条、短划线和裁切线；
- 纹理透明度应低于 4–6%；
- 禁止动态噪声、持续移动纹理和大面积图片背景；
- Night Signal 可将纹理替换为极弱的碳粉/磨砂颗粒，但仍必须保持可读性。

优先使用 CSS background 和内置 SVG，避免外部资源加载。

## 4. 应用壳层

### 4.1 顶栏：纸带式工作区导航

当前 `transport-bar` 保留结构，但视觉重做为一条横向“标题纸带”：

```text
┌ t0 / HDSI ── 连接 ── 剧本 ── 诊断 ── Console ── 故事选择 ── 状态 ── 外观 ┐
```

要求：

- 品牌区使用 `t0` 印章或小型几何标识，颜色由 Indigo/朱红局部承担；
- Surface tabs 像纸带上的章节标签，当前 tab 使用底部色带 + 右下硬影，不使用全块高亮；
- 故事选择器显示故事名、角色/分支短标，点击后打开带故事状态的选择面板；
- 运行状态显示中文主名：`运行中`、`静音中`、`已暂停`、`离线`，保留英文小标签作为辅助；
- 外观、帮助、布局、导入和备份收入“更多/工具”菜单；
- 主动作随页面变化，但同一视口只保留一个实心主 CTA。

### 4.2 Story Pulse：不是装饰的状态尺

将当前 `.status-ruler` 演变为一条“状态尺/工作台刻度”：

- Worker：Ready / 启动中 / 离线；
- Bridge：协议与心跳；
- Channels：在线端点数量；
- Model：当前路由/最近调用；
- Inbox/Outbox：待处理数量；
- 故事时间与本地时间。

每个状态块可点击，点击后定位到：

- 连接配置；
- Diagnostics 日志过滤；
- Deliveries 详情；
- 当前故事 Inspector。

有错误时不要只变色，显示：

```text
需要处理 · 1
```

并提供打开详情的入口。

## 5. Studio V5：纸面故事工作台

### 5.1 Overview 首屏

Overview 是默认进入的故事状态页，不是静态 dashboard。

```text
┌──────────────────────────────────────────────────────────────────┐
│ STORY / 03                         第 18 回合 · 东京 · 20:42    │
│ 雨のち、灯り                                      [聚焦 NOW]    │
├──────────────────────────────────────────────────────────────────┤
│ 当前章节卡                         下一步 / NEXT MOVE           │
│ 章节名、场景、最近叙事摘要           真实可执行的动作              │
│ 纸张折角 / 章节色带                  修复、查看、继续、跳转        │
├──────────────────────────────────────────────────────────────────┤
│ SCRIPT     最近脚本片段 / 场景                              │
│ RECEIVE    入站消息 / 参与者                                │
│ SEND       出站投递 / 回执                                  │
├──────────────────────────────────────────────────────────────────┤
│ 最近活动 / 生活线索 / 待处理项                                │
└──────────────────────────────────────────────────────────────────┘
```

主场景卡使用纸面材质和硬影，但高度受限，不能挤掉三条窄轨。卡片必须包含真实数据：

- 当前场景/章节；
- 最近一条叙事摘要；
- 当前故事时间；
- 模型/端点/待处理提示；
- 可执行的主动作。

若没有场景数据，显示明确空状态和入口，不渲染虚构的故事文案。

### 5.2 三条窄轨

保持 V4 轨道语义：

| 轨道 | 视觉材料 | 交互 |
|---|---|---|
| Script | 紫色章节标签、纸带、正文摘要 | 点击进入 Timeline 并定位脚本 |
| Receive | 靛蓝/湖蓝索引条、来源小章 | 点击查看入站对象、参与者和原文 |
| Send | 沙金/朱红回执标记、目标端点标签 | 点击查看 delivery、失败原因和回执 |

每条轨道：

- 保持固定高度，不因无数据塌陷；
- 显示轨道名、说明、事件计数；
- 至少显示一条最近事件；
- 预览块使用明确按钮语义；
- hover 时出现 `查看`、`定位`、`更多` 等上下文动作；
- 右键菜单和可见动作保持等价；
- 没有数据时提供扩大范围、刷新或检查连接入口。

### 5.3 Overview → Timeline

继续采用 V4 的容器展开与 FLIP，但 V5 增加纸面光影连续性：

1. Overview 预览块保留原位置和硬影；
2. 三条纸带沿垂直方向展开；
3. 时间尺、轨道头和 playhead 逐层出现；
4. 同一 `entityId` 的块移动到 Timeline 位置；
5. 目标块获得青色选中边和短硬影；
6. 360ms 内完成，最后恢复完整交互。

不要对整个 Timeline 使用 `transform: scale()`，避免文字模糊。动画期间：

- `pointer-events` 不应锁死整个工作区；
- 可取消或完成后执行一次定位；
- 快速连续点击只保留最后一个目标；
- snapshot 更新时不得产生空白层；
- reduced motion 直接完成布局切换。

### 5.4 Timeline 的硬光影

- NOW：信号橙竖线、三角旗和“现在”文字；
- 当前时间窗：纸尺/刻度线具有压印感；
- 选中 clip：青色硬边、右下短影和 Inspector 联动；
- hover clip：只出现局部底色和操作点，不改变布局；
- 轨道头：像左侧索引卡，使用固定阴影或底边，随横向时间滚动保持可读；
- 时间线背景：使用压下的 `surface-sunken`，让事件块像贴在其上的纸条；
- 删除/清理等高风险操作：使用朱红标记和范围说明，不能只靠红色按钮。

### 5.5 Inspector：从“看信息”到“下一步”

Inspector 依旧是右侧上下文面板，但 V5 让它更像一张当前对象的工作卡。

**Story：**

- 运行/静音/暂停；
- Worker/Bridge/端点状态；
- inbox/outbox 待处理；
- 最近错误；
- 连接和配置入口。

**Timeline clip：**

- 章节/轨道/时间；
- 摘要/来源；
- 打开详情；
- 复制；
- 从此处分支续写（仅在后端支持时显示）。

**Inbound：**

- platform / accountKey / sender / channel；
- 引用、图片、语音摘要；
- 打开原始事件；
- 回放/处理（仅在实际可用时显示）。

**Delivery：**

- 目标端点；
- 状态；
- 回执；
- unknown 的解释；
- 日志关联入口；
- 不把“重试发送”作为 unknown 的默认动作。

主操作用纸面印章/实体按钮，低频和高风险操作放入 `···`。每个动作说明是否会写数据、是否需要重载、是否影响外部消息。

### 5.6 Detail Dock

现有 tabs 保留：

```text
Script · Events · Deliveries · Model Usage · Data
```

V5 增强：

- active tab 采用纸带标签 + 硬底边；
- Script 提供专注阅读模式，使用更宽行距和正文宽度限制；
- Events/Deliveries 每行提供复制、过滤、跳转日志；
- Data 默认折叠 JSON，提供复制 JSON/路径；
- Detail 头部显示“跟随选择/固定当前对象”；
- 拖拽高度和双击恢复有明确抓手；
- 错误与 unknown 行使用左侧语义色带、图标、文字说明。

## 6. 交互设计：让纸面上的每个对象都能继续工作

### 6.1 三层交互密度

| 层级 | 内容 | 设计方式 |
|---|---|---|
| L1 直接操作 | 运行、暂停、静音、聚焦 NOW、搜索、保存 | 常驻文字按钮，命中区至少 32px |
| L2 上下文操作 | 查看详情、复制、轨道筛选、打开端点、定位日志 | hover、Inspector、行尾菜单和右键同时可达 |
| L3 高风险操作 | purge、重置、强制重载、清空日志 | 诊断区或菜单；执行前显示对象、范围和影响 |

交互元素可以更多，但不能让同一行堆出一排相同权重的按钮。每个对象最多一个直接主动作，其他动作收进“更多”或 Inspector。

### 6.2 硬光影反馈状态

```text
默认：平面纸张 + 细边
Hover：上移 1px + 影子加深一档
Pressed：回落 1px + 硬影缩短
Focus：青色双边/外框 + 不改变布局
Selected：青色或靛蓝色带 + 短硬影
Disabled：无硬影 + 明确禁用原因
Loading：保留纸面位置，显示进度标记，不旋转整块卡片
```

不得通过缩放造成文字跳动。按钮和卡片状态变化优先改变边线、影子和底色。

### 6.3 操作反馈

- 成功：操作处显示完成状态，Toast 作为补充；
- 错误：操作处显示原因、恢复建议和 correlation id；
- 加载：显示正在执行的动作名称；
- 未保存：顶部出现纸签式 `未保存 N 项`，保存/放弃始终可见；
- 禁用：提供 tooltip 或辅助文本说明阻断原因；
- 高风险：确认内容必须包含对象、范围和不可逆影响；
- 异步操作：防止重复提交，并在完成/失败后恢复原焦点。

### 6.4 搜索与快捷键

保留并强化：

- `Ctrl+K`：故事、参与者、端点、事件、日志和命令；
- `?`：当前页面快捷键和术语帮助；
- `Esc`：关闭最上层 dialog/popover，取消转场或搜索；
- `1–4`：Surface/Studio 子视图快捷切换，输入框中不截获；
- `Enter`：执行当前主操作；
- `Ctrl/Cmd+S`：保存当前配置草稿（不自动重载，除非明确页面规则）。

全局搜索结果需显示对象类型、故事、时间和动作；选择结果后切换到对应视图、定位并选中。

## 7. 页面改造建议

### 7.1 Connect / 连接

沿用 V2 的步骤化就绪检查和 V3 Connect 参考稿：

```text
检查环境 → 选择平台 → 测试端点 → 绑定故事
```

视觉上使用纸张步骤卡：

- 已完成步骤像盖章；
- 当前步骤有靛蓝/朱红硬影；
- 未完成步骤保持压下状态；
- 每一步显示检查时间、解释和主操作。

端点卡提供：协议、地址简写、selfId、在线状态、能力矩阵和最近探测结果。Token 默认隐藏；复制/显示是显式操作。保存草稿和保存并重载区分显示，重载影响需要说明。

### 7.2 Mixer / 行为设置

从 V3 Mixer 参考稿继承高密度参数编辑，但将每个参数卡做成“索引卡”而不是普通灰色方块：

- 顶部显示配置来源、有效值、草稿值、待保存数；
- 支持参数搜索和推荐/全部/高级筛选；
- Range 与数字输入同步；
- 继承默认是明确状态；
- 每个参数提供影响对象、保存后生效时机、是否需要重载；
- 当前修改项用左侧朱红/沙金标记和短硬影突出；
- 保存成功后就地盖章式反馈；
- 放弃修改前提示会丢失的字段数量。

### 7.3 Logs / 诊断

Diagnostics 采用“索引档案”风格：

- 顶部先显示健康摘要、待处理项和过滤 chip；
- 继续支持暂停跟随、恢复跟随、加载更早、导出；
- 错误行使用朱红侧边条、错误图标和可复制 correlation id；
- 高频日志保持紧凑，但正文不低于 12px；
- 点击错误可跳到 story/event/delivery/配置对象；
- 空日志状态说明当前过滤器和清除路径。

### 7.4 Koishi Console

区分以下状态：

- Worker 未上报 Console 地址；
- 正在连接；
- 连接拒绝；
- Worker 已停止；
- Console 可用。

每种状态都要有说明和下一步。不能只显示空 iframe 或内部的 `Compatibility Surface` 占位文案。

### 7.5 Dialog / Toast / Popover

- Dialog 像叠在桌面上的白纸/深色卡片，带统一硬影；
- 遮罩只降低背景明度，不使用大面积模糊；
- 打开后焦点落在标题或首个安全控件；关闭后回到触发按钮；
- Popover 具有纸张边缘和短投影，自动避开窗口边缘；
- Toast 像贴纸/索引条，不遮住底部主要控件；
- 错误 Toast 保留更久，并可打开完整详情。

## 8. 主题实现与当前代码映射

### 8.1 当前前端问题

当前主要视觉仍由以下内容共同决定：

- `desktop/src/renderer/style.css` 顶部的深色变量；
- 大量直接写入的 `#xxxxxx` 颜色；
- `index.html` 内嵌布局和菜单样式；
- `workspace-layout.css` 中的轨道/裁切约束；
- `app.js` 中对 `browserView`、`viewMode`、`storyLayouts` 和 Toast 的状态控制。

V5 第一阶段不应重写 `app.js` 的业务状态。应先把视觉层从这些状态中抽离。

### 8.2 CSS 分层

建议整理为：

```text
style.css
  1. theme tokens: paper-studio / night-signal
  2. shadow + material tokens
  3. reset / base controls / focus
  4. app shell / topbar / pulse
  5. reusable paper components
  6. studio / connect / logs / mixer / dialogs
  7. responsive / reduced-motion / high-contrast
workspace-layout.css
  仅负责布局几何、轨道宽度、滚动和裁切
index.html inline style
  逐步移除可复用颜色、边框和组件规则
```

不建议继续向 `style.css` 文件末尾无序追加覆盖。先整理 token，再按组件迁移。

### 8.3 旧变量兼容

迁移初期允许使用旧变量别名，降低回归风险：

```css
:root {

  --panel-2: var(--t0-surface);
  --panel-3: var(--t0-surface-sunken);
  --line: var(--t0-line);
  --text: var(--t0-ink);
  --dim: var(--t0-ink-secondary);
  --faint: var(--t0-ink-muted);
  --accent: var(--t0-sand);
  --green: var(--t0-moss);
  --blue: var(--t0-indigo);
  --red: var(--t0-vermilion);
}
```

完成组件迁移后，逐步删除硬编码色值和旧 alias。`workspace-layout.css` 只保留几何布局，不应承担主题色。

### 8.4 主题选择器

外观菜单提供：

```text
主题
  ○ 纸面工作台 · Paper Studio（默认）
  ○ 夜航 · Night Signal

  ○ 舒适

动效
  ○ 跟随系统
  ○ 减少动效
```

主题预览应使用真实组件小样：按钮、状态 chip、轨道片段、Inspector 和 dialog，不使用纯色方块。

## 9. 响应式、无障碍与长时间使用

### 9.1 断点

- **≥1440px：** Browser、主区、Inspector、Detail 完整显示。
- **1100–1439px：** Inspector 可变为右侧覆盖层；Browser 可折叠；顶栏减少英文副标。
- **860–1099px：** Browser 和 Inspector 至少一个转抽屉；主区保留时间线和基本操作。
- **<860px：** 提示建议展开窗口，但仍允许通过单列抽屉完成核心操作；不能只剩不可读的缩放版三栏。
- 必测系统缩放：100%、125%、150%。

### 9.2 光影与可访问性

- 硬影不是焦点环；焦点必须有独立的高对比双边/外框；
- 主题不能用光影隐藏 disabled、error 或 focus；
- 轨道颜色必须配合图标、文字或线型；
- `prefers-reduced-motion` 关闭 FLIP、副动画和不必要的数值滚动；
- `shadowMode: none` 时仍保留边线、层级背景和焦点环；
- 正文与控件满足 WCAG AA 目标；
- 动态状态使用克制 live region，不每秒播报时钟和播放头；
- 纸面纹理和阴影不能降低小字号文字的清晰度。

### 9.3 长时间使用

- Paper Studio 默认低饱和暖白，不使用纯白背景；
- Night Signal 默认不使用纯黑；
- 阴影面积受限，避免整屏灰雾；
- 正文 14–16px，行高 1.6 以上；
- 日志/时间线可以高密度，但行高不低于 1.4；
- 可单独关闭纹理、硬影和动画，不必切换整个主题。

## 12. 最终推荐

V5 应采用以下主题策略：

```text
默认：Paper Studio
  暖白纸面 + 墨色文字 + 靛蓝/苔绿/朱红
  硬光影工作台

暗色：Night Signal
  墨蓝黑纸面 + 冷灰文字 + 信号橙/青色焦点
  夜间硬边光影
```

优先实施 **V5-A + V5-B**：先把纸面默认主题、硬光影 token、顶栏、Story Pulse、Overview、Timeline、Inspector 和 Detail Dock 做成统一系统，再扩展完整外观偏好和更多交互。

V5 的成功标准不是“看起来更花”，而是：

> **界面像一张真正可工作的故事编辑台；纸张、光影、色带和阴影让层级变得可见；用户不用猜每个对象是什么，也不用猜下一步应该点哪里。**
