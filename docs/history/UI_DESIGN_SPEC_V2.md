# HDSI Desktop typ·0 UI 设计规范 v2

> 状态：设计稿
>
> 适用版本：`HDSI-desktop-typ-0-cev`
>
> 目标：在现有工作台能力上，降低首次使用成本，统一账号与配置入口，提高运行状态的可解释性，并保留时间线、日志和诊断能力。

## 1. 设计目标

### 1.1 产品定位

typ·0 是一个运行 HDSI 剧本的桌面控制台。它同时服务三类任务：

1. **接入**：安装并连接 Worker、模型和消息渠道。
2. **运行**：观察剧本、控制运行状态、处理消息和投递。
3. **维护**：查看日志、配置记忆与行为、检查数据和诊断问题。

界面应该让用户先看到“现在能不能正常运行”和“下一步该做什么”，再提供细粒度参数。

### 1.2 设计结果

- 新用户在不阅读文档的情况下完成首次聊天。
- 账号、渠道和故事之间的关系可以直接看懂。
- 运行、静音、暂停、离线、配置错误、结果未知等状态同时有颜色、文字和行为说明。
- 高级诊断能力保留，但不阻塞日常操作。
- UI 对 QQ、微信及其他 OneBot 账号使用统一的通道中立模型。
- 1280×720 窗口下主要流程仍然可用。

### 1.3 非目标

- 不把桌面端变成完整的 Koishi 管理后台。
- 不在时间线中编辑历史事实；时间线默认是只读观察和定位工具。
- 不让用户直接修改运行时数据库。
- 不用动画替代状态文字或错误说明。

## 2. 当前问题基线

当前渲染器主要位于：

- `desktop/src/renderer/index.html`
- `desktop/src/renderer/style.css`
- `desktop/src/renderer/workspace-layout.css`
- `desktop/src/renderer/app.js`

现有能力已经覆盖连接、Studio、Logs、Koishi、时间线、Session、Mixer、Stats、Analysis 和配置。主要体验问题如下：

| 问题 | 影响 | 设计处理 |
|---|---|---|
| 顶栏操作过多 | 小窗口拥挤，状态不容易读 | 顶栏只保留当前故事、运行状态和主要动作，其余收入更多菜单 |
| Browser、Inspector、Detail 术语偏内部 | 新用户不知道各区域职责 | 使用中文主名称和英文副名称，补充对象类型 |
| 连接页是若干并列卡片 | 用户不清楚配置顺序 | 改成步骤化就绪检查 |
| 账号入口重复 | 连接页和侧栏可能产生修改冲突 | 连接页作为唯一写入口，侧栏只读摘要 |
| QQ 数字账号校验 | 无法表达微信或非数字 OneBot ID | 使用 channel/platform/selfId 三层字段 |
| YAML 与结构化配置分离 | 保存时容易丢另一侧修改 | 使用统一草稿、变更摘要和保存策略 |
| 状态依赖颜色和灯 | 色弱、低亮度环境下难以判断 | 颜色 + 图标 + 文字 + 行为说明 |
| 分析图表不可追溯 | 看到异常后不能定位原始事件 | 图表点支持详情和时间线跳转 |

## 3. 信息架构

### 3.1 一级区域

顶层导航固定为四项：

| 中文名称 | 英文副标 | 职责 |
|---|---|---|
| 连接 | Connect | Worker、模型、渠道、账号和就绪检查 |
| 剧本 | Studio | 当前故事的观察、时间线、片段和运行控制 |
| 诊断 | Diagnostics | 日志、投递记录、模型用量、错误和系统健康 |
| Console | Koishi | 打开当前 Worker 的隔离 Koishi Console |

`Logs` 不再作为独立一级概念展示给普通用户，而是作为“诊断”中的默认子页。保留快捷键和内部路由别名以兼容现有代码。

### 3.2 Studio 子导航

左侧 Browser 中的故事相关视图改为：

1. 总览 Overview
2. 时间线 Timeline
3. 片段 Session
4. 设置 Settings
5. 事实与场景 Facts & Scenes
6. 计划 Schedule
7. 统计 Stats
8. 分析 Analysis

当前的 Mixer 作为 Settings 的高密度编辑视图保留，但默认名称显示为“行为设置”。

### 3.3 右侧与底部面板

- **摘要 Inspector**：当前对象的身份、状态、关键指标和下一步操作。
- **详情 Detail**：完整剧本、事件、投递、模型用量或数据 JSON。
- **底部面板**默认打开，但记住用户的折叠状态。

对象层级必须明确显示：

```text
故事摘要 → 事件摘要 → 事件完整内容
```

### 3.4 全局操作

全局主要操作：

- 新建剧本
- 导入剧本
- 搜索功能（Ctrl+K）
- 打开帮助（?）
- 备份

导入、帮助、布局、备份放入右上角“更多”菜单；“新建剧本”保留为顶栏主按钮。

## 4. 应用壳层布局

### 4.1 桌面布局

```text
┌─────────────────────────────────────────────────────────────────────┐
│ Brand | 一级导航 | 当前故事 | 状态文字 | 主要动作 | 更多             │
├─────────────────────────────────────────────────────────────────────┤
│ 当前故事摘要 / Worker / 通道 / 模型 / 当前时间                      │
├───────────────┬──────────────────────────────────────┬──────────────┤
│ Story Browser │                                      │  Inspector   │
│               │              Workspace               │              │
│               │                                      │              │
├───────────────┴──────────────────────────────────────┴──────────────┤
│ Detail / Events / Deliveries / Usage / Data                          │
└─────────────────────────────────────────────────────────────────────┘
```

### 4.2 尺寸

| 区域 | 默认 | 最小 | 说明 |
|---|---:|---:|---|
| 顶栏 | 44px | 44px | 主要按钮和故事选择 |
| 状态栏 | 32px | 28px | 状态摘要和时间 |
| Browser | 248px | 196px | 可拖动，窄屏改抽屉 |
| Inspector | 300px | 240px | 可拖动，窄屏改覆盖层 |
| Detail | 210px | 96px | 可拖动，支持折叠 |
| 主工作区 | 剩余空间 | 420px | 时间线和卡片视图 |

### 4.3 顶栏规则

顶栏从左到右：

1. 品牌标志和当前 Worker 状态。
2. 一级导航。
3. 当前故事选择器。
4. 当前运行状态文字和图标。
5. 新建剧本主按钮。
6. 更多菜单。

运行状态必须同时显示文字：

- `运行中 · 正常收发与自动推进`
- `静音中 · 继续生成但不发送`
- `已暂停 · 新消息进入收件箱`
- `离线 · Worker 未加载`

原有 `▶ / ◐ / ■` 仍可保留作为图标，但不可作为唯一含义来源。

### 4.4 状态栏

状态栏显示四个摘要：

```text
故事：小桃线     Worker：Ready     通道：QQ 在线     模型：可用     2026-09-29 21:40
```

状态来源必须区分：

- Worker 状态
- bridge 状态
- 消息渠道状态
- 模型状态
- 最近一次错误

不要用一个 `WORKER OFFLINE` 字段代表所有故障。

## 5. 连接页设计

### 5.1 页面结构

左侧为按顺序排列的连接步骤，右侧为当前故事的“就绪检查”。

```text
连接与账号
┌──────────────────────────┬───────────────────────────────┐
│ 1 Worker                  │ 当前故事就绪检查               │
│ 2 模型                    │ ✓ Worker                       │
│ 3 消息渠道                │ ✓ 模型                         │
│ 4 账号                    │ ! 账号未绑定                   │
│ 5 交往对象                │ ! 白名单为空                   │
│                          │ [修复全部阻断项]               │
└──────────────────────────┴───────────────────────────────┘
```

### 5.2 步骤卡片

每张卡片包含：

- 步骤编号；
- 状态图标；
- 当前状态文字；
- 最近检查时间；
- 一句解释；
- 一个主操作；
- 一个“查看详情”入口。

状态统一为：

- `未配置`
- `检查中`
- `已就绪`
- `需要处理`
- `不可用`
- `被跳过`

### 5.3 通道中立账号表单

账号表单使用以下字段：

```ts
interface AccountForm {
  channelKind: 'qq' | 'wechat' | 'other'
  platform: string
  selfId: string
  displayName: string
  upstreamEndpoint?: string
  tokenAlias?: string
}
```

交互规则：

- `channelKind` 先选，平台字段根据通道显示默认值；
- `selfId` 允许非数字字符串；
- 账号 ID 旁显示示例和合法字符说明；
- 账号唯一性错误必须指出冲突故事；
- 绑定成功后显示“账号 → 故事”的关系卡片；
- 解绑必须显示影响范围和恢复方式。

### 5.4 首次接入流程

1. 检测 Worker。
2. 检测消息渠道。
3. 选择或创建故事。
4. 绑定账号。
5. 配置模型。
6. 配置交往对象。
7. 发送测试消息。
8. 显示第一次成功收发的时间和消息 ID。

所有异步检查都必须显示进度，不能只替换成“正在检测”。

## 6. 新建剧本向导

### 6.1 向导步骤

将现有五步向导调整为：

1. 角色是谁
2. 从哪里开始
3. 使用哪个模型
4. 通过哪个通道
5. 谁可以聊天
6. 创建前检查

“通道”与“模型”不应要求用户在故事创建时必须配置。允许跳过，但必须在最终检查页显示阻断或待处理状态。

### 6.2 创建前检查

检查页使用清单，而不是一段文本：

| 项目 | 当前值 | 状态 | 操作 |
|---|---|---|---|
| 故事名称 | 小桃线 | 已完成 | 编辑 |
| 主角设定 | 已填写 | 已完成 | 编辑 |
| 模型 | 未配置 | 可稍后处理 | 配置 |
| 通道 | QQ / 账号 A | 已完成 | 编辑 |
| 白名单 | 2 人 | 已完成 | 编辑 |

提交按钮文案根据状态变化：

- `创建剧本`
- `创建并开始运行`
- `创建，稍后配置`

## 7. Studio 总览

### 7.1 总览内容

总览不是空白时间线，而是当前故事的运行摘要：

```text
小桃线
运行中 · Worker Ready · QQ 在线

[继续运行] [静音] [暂停] [配置]

最近活动       2 条待处理消息       最近回复 18 秒前
模型状态       主模型可用           今日约 0.12 元
记忆状态       事实 42 条            上次压缩 2 小时前
```

### 7.2 空状态

每种空状态都必须给出原因和行动：

- 未选择故事：`从左侧选择一个故事，或创建新剧本。`
- Worker 未加载：`加载 Worker 后才可读取时间线。` + `加载 Worker`
- 没有时间线数据：`当前范围内没有事件。` + `回到 NOW` / `扩大时间范围`
- 模型未配置：`还不能生成剧本。` + `配置模型`

## 8. 时间线设计

### 8.1 轨道顺序

默认顺序：

1. Script
2. Receive
3. Send
4. Media
5. Alter
6. Facts & Scenes
7. Schedule
8. Compaction

维护轨道默认折叠，用户可在轨道菜单中显示。

### 8.2 轨道视觉

颜色只用于辅助，轨道头必须同时显示图标、名称和数量。

| 轨道 | 颜色 | 辅助图标 | 语义 |
|---|---|---|---|
| Script | 粉紫 | 文本 | 模型生成的剧本 |
| Receive | 蓝色 | ↓ | 用户收到的消息 |
| Send | 橙色 | ↑ | 角色实际发出的消息 |
| Media | 青绿色 | 图片/音频 | 附件消息 |
| Alter | 紫色 | 波形 | 情绪惯性 |
| Facts | 淡紫 | 菱形 | 长期事实 |
| Schedule | 棕色虚线 | 日历 | 未来计划 |
| Compaction | 黄色 | 压缩 | 后台维护 |

### 8.3 Clip 规则

Clip 至少显示：

- 起止时间；
- 类型；
- 一行内容摘要；
- 投递状态或来源端点；
- 是否为推断数据。

Hover 卡片显示完整信息；点击后 Inspector 显示摘要，底部 Detail 显示完整内容。

### 8.4 时间控制

- `NOW` 为明确的文字按钮，而不是只有黄色播放头；
- 时间缩放旋钮旁显示当前范围，例如 `14 小时`；
- 支持“回到现在”“最近 24 小时”“最近 7 天”“自定义范围”；
- 用户拖动范围后，必须在标尺上显示 `当前窗口：...`；
- 刷新按钮显示最近刷新时间和失败原因。

## 9. Session 片段视图

Session 用于按剧本片段浏览，不使用过多 DAW 术语。

每个片段卡片包含：

- 编号；
- 起止时间；
- 包含的条目数；
- 内容摘要；
- 分支按钮；
- 查看详情按钮。

分支操作必须在确认页明确说明：

- 使用哪个 entry 作为锚点；
- 是否复制完整剧本库；
- 原故事是否受影响；
- 创建完成后是否自动切换。

## 10. 行为设置与配置

### 10.1 设置分层

设置分为三层：

1. **快速预设**：联系频率、费用优先、聊天范围、日志密度。
2. **常用参数**：模型、白名单、群聊、记忆、主动联系。
3. **高级参数**：YAML、扩展能力、诊断和实验项。

### 10.2 草稿模型

所有配置编辑使用统一 Draft：

```ts
interface ConfigDraftState {
  storyId: string
  baseRevision: string
  values: Record<string, unknown>
  dirtyPaths: string[]
  source: 'structured' | 'yaml' | 'mixed'
  validation: ValidationIssue[]
}
```

保存策略：

- 保存全部草稿；
- 保存当前分区；
- 放弃全部修改；
- 预览变更。

如果 YAML 与结构化表单存在冲突，必须显示字段级冲突，而不是只弹一句确认框。

### 10.3 高风险操作

“保存并重载”“解绑账号”“删除故事”“删除时间范围”必须使用统一确认组件，显示：

- 影响对象；
- 是否中断当前生成；
- 是否会丢弃未发送消息；
- 是否已有备份；
- 恢复方法。

## 11. 诊断页

### 11.1 日志

日志页顶部提供快捷过滤：

- 错误
- 警告
- 投递
- 模型
- 连接
- Worker

高级过滤仍保留等级、来源、文本和 correlation ID。

日志行点击后：

- 展开完整内容；
- 显示故事、Worker、来源和 correlation ID；
- 提供“跳转到故事”“跳转到事件”“复制详情”。

“清空视图”只清理当前显示，不删除日志文件；按钮文案必须明确写出这一点。

### 11.2 投递详情

投递状态统一使用文字：

- 已生成
- 发送中
- 已受理
- 已确认
- 结果未知
- 可重试失败
- 永久失败

每条投递显示：目标、端点、时间、段落序号、重试次数和错误原因。

### 11.3 模型用量

显示：

- 今日输入 token；
- 今日输出 token；
- 缓存命中率；
- 调用次数；
- 估算费用；
- 按任务和提供商拆分。

所有统计卡片都要显示时间范围和更新时间。

## 12. Analysis 设计

### 12.1 分析卡片

分析页包含：

1. 压缩健康
2. 叙事连贯性
3. 情绪与场景
4. 语义记忆地图

每张卡片必须显示：数据范围、更新时间、数据是否完整、计算失败原因。

### 12.2 可追溯性

- 图表点可点击；
- 点击后在 Inspector 查看原始条目；
- 提供“定位到时间线”；
- 事实地图节点显示事实摘要、重要性和置信度；
- 提供表格视图作为图表的无障碍替代。

### 12.3 统计口径

不要只显示“近似”而不解释。每个近似指标旁提供 tooltip：

- 数据来源；
- 计算范围；
- 缺失数据如何处理；
- 何时应当忽略该指标。

## 13. Koishi Console

Console 页面保留隔离嵌入，但状态需要分层：

- Worker 未加载；
- endpoint 未上报；
- endpoint 已就绪；
- 正在嵌入；
- 嵌入失败；
- endpoint 已撤销。

错误页提供：

- 重试嵌入；
- 在浏览器打开；
- 查看 Worker 日志；
- 复制诊断信息。

不要在普通 UI 中展示 token 或带认证信息的 URL。

## 14. 视觉设计规范

### 14.1 色彩 Token

```css
:root {
  --bg: #202326;
  --surface-1: #292d31;
  --surface-2: #32373c;
  --surface-3: #3b4248;
  --border: #4b555d;
  --border-soft: #384047;
  --text: #eef1f3;
  --text-secondary: #c0c8ce;
  --text-muted: #929da5;
  --text-disabled: #68727a;
  --accent: #f5c542;
  --success: #8dcc68;
  --info: #76b9ed;
  --warning: #e3ad55;
  --danger: #e57d7d;
  --script: #d77bb6;
  --receive: #79b8ed;
  --send: #e8aa75;
  --media: #62b7a5;
  --facts: #b394df;
}
```

原有 `--faint: #727272` 只用于装饰性文字，不能用于关键状态或正文。

### 14.2 字体

- 中文正文：`Segoe UI`, `Microsoft YaHei`, sans-serif；
- 数据和 ID：`Consolas`, `Cascadia Code`, monospace；
- 正文最小 12px；
- 辅助说明最小 11px；
- 状态和按钮不得低于 12px；
- 行高：正文 1.5，日志 1.4，表单说明 1.6。

### 14.3 形状与间距

- 默认圆角 4px；
- 主要卡片间距 12px；
- 表单控件高度 30–34px；
- 主要按钮高度至少 32px；
- 使用 4px 间距基准：4、8、12、16、24、32。

### 14.4 状态表达

状态必须满足：

```text
颜色 + 图标 + 文字 + 说明 + 可执行动作
```

示例：

```text
● 需要处理
模型 API Key 未配置
[打开模型配置]
```

## 15. 响应式策略

### 15.1 断点

| 宽度 | 布局 |
|---:|---|
| ≥ 1440px | Browser + Workspace + Inspector + Detail |
| 1120–1439px | 缩窄三栏，Detail 保留 |
| 860–1119px | Browser + Workspace，Inspector 改覆盖层 |
| < 860px | Browser 改抽屉，Detail 改底部抽屉 |

### 15.2 窄屏行为

- 顶栏隐藏次要按钮；
- 故事选择器改为全宽弹层；
- Inspector 使用“查看摘要”按钮打开；
- 轨道头固定，但缩短到 96px；
- 时间线保持横向滚动，不压缩到无法阅读；
- 配置对话框变为全屏页面。

### 15.3 系统缩放

在 Windows 125% 和 150% 缩放下：

- 不能出现文字裁切；
- 不能依赖固定像素高度显示完整按钮；
- 不能让顶栏控件互相覆盖；
- 弹窗必须保留关闭和保存按钮。

## 16. 无障碍规范

- 所有图标按钮提供 `aria-label`；
- 一级导航使用 `role="tablist"`，面板使用 `role="tabpanel"`；
- 状态变化区域使用 `aria-live="polite"`；
- 错误和危险操作使用 `aria-live="assertive"` 或明确焦点转移；
- 键盘可以完成连接、创建、保存、切换故事和关闭弹窗；
- Tab 顺序与视觉顺序一致；
- 不以颜色作为唯一状态信息；
- SVG 图表提供数据表格或文本摘要；
- 弹窗打开后焦点进入标题或第一个可操作控件，关闭后返回触发按钮；
- 支持减少动态效果：`prefers-reduced-motion: reduce` 时关闭淡入、播放头动画和过渡。

## 17. 动效与反馈

### 17.1 动效原则

- 状态切换：100–160ms；
- 面板打开：160–220ms；
- 数据加载：不使用无限旋转，使用明确文字和阶段进度；
- 错误出现时不抖动、不闪烁；
- 动效不能阻止键盘和鼠标操作。

### 17.2 Toast

Toast 只用于短反馈，不承载关键错误。

| 类型 | 使用 |
|---|---|
| success | 保存成功、绑定成功、导出完成 |
| info | 状态切换、开始加载 |
| warning | 结果未知、需要重试 |
| error | 保存失败、连接失败 |

关键错误必须同时保留在 Inspector、日志或就绪检查中。

## 18. 数据与前端状态约束

### 18.1 Story UI 状态

```ts
interface StoryViewState {
  selectedStoryId?: string
  phase: 'running' | 'muted' | 'paused' | 'offline' | 'error'
  worker: 'offline' | 'booting' | 'ready' | 'error'
  bridge: 'unknown' | 'connecting' | 'ready' | 'revoked'
  channel: 'unknown' | 'offline' | 'connecting' | 'online' | 'error'
  model: 'unknown' | 'missing' | 'ready' | 'error'
  inboxPending: number
  outboxPending: number
  lastError?: UserFacingError
}
```

### 18.2 不允许的 UI 行为

- 异步请求返回后覆盖已切换故事的页面；
- 异步失败只写 console，不向用户显示；
- 保存失败后显示“已保存”；
- 外部连接失败后继续显示“在线”；
- 用旧故事的账号状态覆盖新故事；
- 用单一颜色表示多个不同语义。

### 18.3 刷新策略

- 故事列表：事件驱动更新；
- 连接状态：连接事件 + 30 秒低频刷新；
- 时间线：事件触发后 2 秒防抖刷新；
- 分析：手动刷新，显示缓存时间；
- 日志：增量追加，按 ID 去重；
- 统计：按当前时间范围刷新。

## 20. 验收标准

### 首次使用

- 新用户可以在 5 分钟内完成 Worker、模型、通道和账号配置；
- 任一阻断项都有明确原因和操作按钮；
- 成功发送测试消息后，界面显示端到端结果。

### 日常运行

- 用户无需打开日志即可知道故事是否运行；
- 运行/静音/暂停的行为差异在按钮旁可见；
- 账号、渠道和故事关系可在一个页面确认；
- 时间线条目可以定位到事件、投递或日志。

### 配置安全

- 未保存修改不会静默丢失；
- YAML 与结构化配置冲突时显示冲突路径；
- 保存并重载显示中断影响；
- 解绑、删除和清理操作显示恢复路径。

### 视觉和无障碍

- 主要正文不低于 12px；
- 状态不依赖颜色单独表达；
- 键盘可以完成主要流程；
- 1280×720 无重叠、无裁切、无不可达操作；
- 开启减少动效后仍能识别所有状态变化。
