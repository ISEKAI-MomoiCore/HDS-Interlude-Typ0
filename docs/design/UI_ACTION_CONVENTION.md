# typ-0 副作用操作交互公约

- 日期：2026-10-18（P1"提交事务"提案的保守实施批次）
- 性质：**既有模式的形式化**——本文档把散落在各动作点的纪律收成可评审的检查单，防未来漂移，不是新框架。所有条目在现有代码中已有锚点，新增副作用动作时照单实施。
- 明确不做：统一 `idle→validating→applying→verifying` 状态机框架。理由：动作面有限（约 20 处）且已逐点设防；多数动作是单次 IPC 调用， phases 不可分离；保存/重载两段式（用户决定何时中断 worker）优于一体化事务。

## 检查单（新增副作用动作时逐条过）

### 1. 确认框五要素

破坏性/大影响操作（删除、清理、解绑、卸载、高危插件启用）的确认文案必须说明：

1. **具体对象**（哪个剧本/哪个账号/哪个时间区间）
2. **影响**（会发生什么）
3. **可逆性**（不可撤销？软删？有备份？如何恢复）
4. **是否停止收发**（在途消息是否丢失）
5. **是否删除历史**（明确说"不删"和明确说"删"同样重要）

**范本**（解绑确认，app.js `unbindAccount` 流程）：

> 解绑影响范围：该剧本将立即停止收发此账号的消息（在途消息可能丢失）；剧本本身、历史记录与其它配置不受影响。
> 恢复方式：随时可在连接页重新接入该账号。继续吗？

其它参照：选区删除（"不可撤销（软删，Canon 保留）"）、删除剧本（"主进程会先创建备份"）、重载 Worker（"中断生成中的回复和待发投递，但不会删除剧本数据"）、高危插件启用（冲突机理说明）。

### 2. 防重复提交 + 按钮态

- 动作执行期间按钮 `disabled`，文案换成进行时（"回放中… / 安装中… / 更新中… / 卸载中… / 加载中…"）。
- 失败后恢复可点；失败态文案不假装成功（"加载失败 · 关闭后重试"）。
- 表单类提交加提交锁（参照向导的 `wizardSubmitting` 双守卫）。
- 关联按钮组同步禁用（"保存全部"与"保存"随配置加载状态同步——UI P2 批次）。

### 3. 失败保留用户草稿

- 编辑器/表单本身就是草稿载体：失败路径**不清空、不重置**任何用户输入。
- 脏状态跟踪 + 切页/关闭拦截（"配置有未保存的修改，确定丢弃？"）。
- 保存成功也不清草稿——只标记已保存状态。

### 4. 运行态澄清（保存 ≠ 生效）

- 配置保存成功后必须说明 Worker 仍运行旧配置：主进程广播固定措辞"配置已保存；Worker 仍运行旧配置，等待用户确认重载"。
- 重载是用户的显式决定（有确认框，说明会中断什么），不静默执行。
- 数据侧配套：mediator 备份（保留 20 份）+ 临时文件原子 rename + worker 拒载后回滚（`restore`）。

### 5. 结果未知 ≠ 失败（"结果待核实"）

请求已写出但回执未达（超时/进程死亡）的操作，措辞必须：

- 说明**结果不可知**（可能已生效）；
- 给出**核对路径**（刷新时间线 / 查插件面板已装版本）；
- 明确重试是否安全；不安全时禁止诱导立即重试。

这是桥接层 ambiguous/pending 语义（rc56 起，`BridgeRequestAbortedError` / 投递 `unknown` 状态）在 UI 动作层的对应物——同一套词汇，跨层一致。已落地的两处：

| 路径 | 实现 |
|---|---|
| 选区删除回执超时（60s） | `stories.ts requestPurgeRange`：`BridgeRequestTimeoutError` → 翻译为"结果不可知（可能已删除）。请先刷新时间线核对实际删除范围；确认未删后再重试" |
| 插件安装/更新/卸载 npm 超时（5min，进程被杀） | `plugin-installer.ts npm()`："结果不可知（依赖可能已部分写入）。重试安全；重试前可先在插件面板核对已装版本" |

超时错误类型化为 `BridgeRequestTimeoutError`（code=`bridge-timeout`）；**消息文本必须保留"确认超时"字样**——message-router 以 `/超时/` 正则区分 worker-timeout 与 worker-rejected（D2-3），改字会破坏收件箱归因。合同测试见 `bridge-session.test.ts`（类型 + 字样 + 翻译路径 + 非超时透传）。

## 评审提示

Code review 遇到新增副作用动作时，按上面五条对照；文案改动触碰"确认超时"字样或解绑范本结构的，需要说明为什么不破坏 router 分类与五要素。
